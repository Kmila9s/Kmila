# 「运行」到底是什么意思？

当你在 Kmila 里按下 **Run** 时，模拟器并没有真的去点亮一块
FPGA。它只是一步一步地走过你的 VHDL 代码——但**怎么**走，
取决于代码写在哪里。

有三种执行模型，人们经常把它们搞混：

| 模型 | 含义 | 在 VHDL 里出现的位置 |
|---|---|---|
| **顺序（Sequential）** | 一次一条语句，按源代码顺序执行。 | `process` 主体内部。 |
| **并发（Concurrent）** | 多条语句「一起」求值——文件里的先后顺序无关紧要。 | architecture 里 `begin` 和 `end` 之间的并发语句。 |
| **并行（Parallel）** | 在真实的墙上时钟同一瞬间发生多件事。 | **只在真实硬件上。** 仿真中永远不会。 |

下面的例子刻意做得很小——一个 process 读入两个输入
`a` 和 `b`，写出一个输出 `sum`。在播放器里按 ▶，看看
模拟器此刻正在「看」哪一行。

```text
Sequential:   line 1  →  line 2  →  line 3  …
Concurrent:   lines 1 and 2 and 3 all evaluate this instant
Parallel:     not a thing in simulation. Only happens on the FPGA itself.
```

## 为什么这件事重要

初学者读到 `sum <= b;` 常常会以为 `sum` 的值会**立刻**
变成 `b`，就像 C 语言里的 `sum = b;` 那样。其实不是。
这个赋值只是**登记了一个事务**，新值要等到当前 delta
周期结束后才会真正可见。

右侧的播放器把一段短短的执行过程写死在里面——它并没有真的
在跑仿真。这样做是为了让讲解保持诚实：每一步都会附带
一条教学注解，你不必猜测真实模拟器在想什么。

> **试一试：** 手动前进几步，观察 `sum` 一直停留在 `U`
> （未初始化）——即便走到第 3 步之后依然如此，它只有等到
> 第 4 步 delta 周期结束时才会改变。
