# 为什么要给 CPU 加流水线?

你之前的单周期 8 位 CPU 能跑 —— 但在真实硬件上极为关键的一个维度上它受限:**时钟频率**。

## 单周期的天花板

单周期设计中,时钟周期必须长到能让关键路径最长的指令完整传播:fetch → decode → 寄存器读 → ALU → 内存 → writeback,全部都是组合电路。最长路径 20 ns 的话,最大时钟就是 50 MHz。就这么简单。

## 流水线就是把这条路径切开

把路径切成 N 个由寄存器隔开的阶段:

```
  [IF] → [ID] → [EX] → [MEM] → [WB]
    ^      ^      ^       ^       ^
    +------+------+-------+-------+
         阶段之间的寄存器
```

现在时钟只需要让最长的*那个阶段*跑完,不必跑完整条路径。五级,每级 ~4 ns,就能跑到 250 MHz 时钟。吞吐量从 1 条指令 / 20 ns 提到 1 条指令 / 4 ns —— **5× 加速**,概念上是白送的。

## 冒险(Hazard)—— 代价

实际上拿不到完整的 5×。三种碰撞:

- **数据冒险** —— 指令 N+1 要读的寄存器,指令 N 还在写。解法:旁路(forwarding)或者插入 stall 周期。
- **控制冒险** —— 指令 N 是个分支,而我们还没确定要不要执行 N+1 就已经把它取回来了。解法:分支预测或者 flush 流水线。
- **结构冒险** —— 两个阶段同时需要同一个物理资源(比如同一个内存端口)。解法:把资源复制一份,或者串行化。

本模块后续每节课都在课程的 8 位 CPU 上挨个实现一种解法,先从旁路开始。

## 要记住的

- 流水线用**单指令延迟**(更高)换**吞吐**(高得多)。
- 时钟加速被最长那一级封顶,不是最短那一级。
- 冒险要花周期,补救要花门电路。真实 CPU 设计就是把这种权衡放大。
