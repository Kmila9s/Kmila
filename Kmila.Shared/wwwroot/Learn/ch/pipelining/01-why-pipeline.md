# 为什么要给 CPU 加流水线?

你前面那条线里的单周期 8 位 CPU 能跑——但它在一个对真实硬件极其要紧的维度上受限:**时钟频率**。

## 单周期的天花板

在一个单周期设计里,时钟周期必须长到能让关键路径最长的那条指令一路传播完:取指 → 译码 → 寄存器读 → ALU → 访存 → 写回,全都是组合的。如果最长路径是 20 ns,你的最大时钟就是 50 MHz。没得商量。

## 流水线就是把那条路径切开

把路径切成 N 个由寄存器隔开的级:

```
  [IF] → [ID] → [EX] → [MEM] → [WB]
    ^      ^      ^       ^       ^
    +------+------+-------+-------+
         级与级之间的寄存器
```

现在时钟只需要长到能让最长的*那一级*完成,而不是整条路径。五级,每级约 4 ns,就给出一个 250 MHz 的时钟。吞吐从 1 条指令 / 20 ns 提到 1 条指令 / 4 ns——概念上,**5 倍加速**,白送的。

注意流水线*没有*改善什么:任何单条指令的延迟。一条指令仍然要走完五级才算完成——大约 20 ns,和以前一样(其实还略多一点,因为每个边界上有寄存器的建立时间)。变的是:一旦流水线填满,每个周期就有一条*新的*指令完成。你不是让一辆车跑得更快;你是把一个工人变成了一条流水线。

## 级间寄存器

级与级之间的寄存器不是记账用的——它们*就是*流水线。每一个都锁住下游各级仍然需要的所有东西:部分结果、目的寄存器号、在 ID 里译出来的控制信号。没有它们,第 N+1 级就会在计算中途看到第 N 级的输入变掉。这些就是 ESCOM 教学大纲(第四单元)要求你在 HDL 里实现的"级间寄存器"。

## 为什么你实际永远拿不到 5 倍

理想是一旦流水线填满就 **CPI = 1**(每条指令一个周期)。有两样东西会把它侵蚀掉:

1. **填充与排空。**第一条指令仍然要走完所有五级才有东西退出,所以一段很短的程序要付一笔启动开销。对一段很长的运行这可以忽略;对一个紧凑的循环就不行。
2. **冒险**——真正的税,也是本模块其余部分的主题。

## 冒险(Hazard)——代价

三种碰撞,各有各的修法:

**结构冒险**——两个级在同一个周期想要同一个物理资源。经典情形:IF 想读一条指令,而 MEM 想读数据,但只有一个存储器端口。修法:把指令存储器和数据存储器分开(一个哈佛式的拆分),或者把端口复制一份。

**数据冒险**——指令 N+1 需要一个指令 N 还没写回的值:

```
  ADD R1, R2, R3   -- 结果在 EX 末尾就绪,在 WB 里写入
  SUB R4, R1, R5   -- 在它自己的 EX 里就需要 R1,只晚了一个周期
```

没有帮助的话,SUB 读到的是*旧的* R1。修法是**转发**(forwarding,也叫 bypassing):把 ALU 结果直接从 N 的 EX/MEM 输出送回 N+1 的 ALU 输入,而不是等它慢慢爬过 WB、再从寄存器堆里出来。转发消除了大部分数据停顿——但不是全部。**load-use 冒险**是最顽固的那个:一个 load 的值要到 MEM 末尾才可用,比 EX 晚了*一级*,所以一条紧接着用它的指令,无论你的转发多好,仍然必须**停顿一个周期**(插入一个气泡)。

**控制冒险**——指令 N 是一个分支,而在它还不知道分支是否跳转之前,流水线就已经取回了 N+1(也许还有 N+2)。修法:

- **停顿 / 冲刷(flush)**——冻住取指直到分支定下来,或者让错误路径上的指令先开始、一旦猜错就把它们压掉。更早解析分支(在 ID 里而不是 EX 里)能把代价缩到一个气泡。
- **静态预测**——在编译期总是朝一个方向猜(例如"向后的分支会跳转",这对循环抓得很准)。
- **动态预测**——在运行期学习,用一张由分支地址索引的 **2 位饱和计数器**表。计数器需要连着*两次*猜错才会翻转它的预测,所以一个跳转了 99 次然后退出一次的循环,不会立刻改主意。计数器处在两个高状态时预测"跳转",处在两个低状态时预测"不跳转";每次跳转就把它朝跳转推一点,否则朝不跳转推。便宜,而且它几乎做得和那些精巧得多的方案一样好。

本模块后面的每一课都在课程那颗 8 位 CPU 上一次实现一种修法,从转发开始——对应 ESCOM 的递进:结构 → 数据 → 旁路/转发 → 控制冒险。

## 要点

- 流水线用**每条指令的延迟**(不变,甚至略高)换**吞吐**(高得多):理想 CPI → 1。
- 时钟的加速被最长的*那一级*封顶,不是整条路径,也不是最短的那一级。
- 级间寄存器把数据*和*控制一起往前带;正是它们让这种重叠是安全的。
- 转发抹掉大部分数据冒险,但一对 load-use 仍然要花一个停顿。分支要花一次冲刷,除非你预测它——一个 2 位饱和计数器就是那个主力预测器。
- 冒险花周期;缓解措施花门电路。真实的 CPU 设计就是把这种权衡放大。
