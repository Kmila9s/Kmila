# 为什么要给 CPU 做流水线？

你在前面课程里写的那台单周期 8 位 CPU 能跑 —— 但在一个在真实硬件上影响极大的维度上受到限制：**时钟频率**。

## 单周期的上限

在单周期设计中，时钟周期必须长到让关键路径最长的指令从取指 → 译码 → 读寄存器 → ALU → 访存 → 写回一路以组合方式传播完。如果最长路径是 20 ns，你的最高时钟就是 50 MHz。就这样。

## 流水线就是把这条路径切开

用寄存器把这条路径分成 N 段：

```
  [IF] → [ID] → [EX] → [MEM] → [WB]
    ^      ^      ^       ^       ^
    +------+------+-------+-------+
         段间寄存器
```

现在时钟只需要长到让最慢的*段*完成即可，而不是整条路径。五段，每段 ~4 ns，得到 250 MHz 时钟。吞吐率从 1 条指令/20 ns 变成 1 条指令/4 ns —— 概念上**白捡 5 倍加速**。

## 冒险 —— 代价

实际中你拿不到 5×。三类冲突：

- **数据冒险** —— 第 N+1 条指令读的寄存器正好是第 N 条仍在写的。修正：加转发路径或插入停顿周期。
- **控制冒险** —— 第 N 条是分支，而在知道是否要执行之前我们已经取了第 N+1 条。修正：分支预测或流水线冲刷。
- **结构冒险** —— 两个阶段需要同一块物理资源（例如一个存储端口）。修正：复制资源，或串行化。

本模块后续每一课都在课程的 8 位 CPU 上一次实现一种修正，首先是转发。

## 关键要点

- 流水线用更高的**单条指令延迟**换取远高得多的**吞吐率**。
- 时钟加速的上限由最长段决定，而不是最短段。
- 冒险耗周期，缓解冒险耗门电路。真实的 CPU 设计就是在这类权衡上做规模化。
