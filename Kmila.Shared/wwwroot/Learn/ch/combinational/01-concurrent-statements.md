# 并发赋值：`when/else` 与 `with/select`

VHDL 中的组合逻辑是用并发语句写的 —— 进程（process）以外的每一行都在描述一段永久连线的硬件。完成同一件事有两种语法形式：**条件赋值**与**选择赋值**。

## `when/else` —— 条件赋值

当你有一组按优先级排列的条件，或者每个分支检查不同的信号时比较合适：

```vhdl
y <= '0' when reset = '1' else
     a   when mode  = "read" else
     b   when mode  = "write" else
     'Z';
```

第一个匹配的条件胜出。顺序至关重要 —— 它会被综合成一个**优先级多路选择器**：最顶层的条件到 `y` 的路径最短。

## `with/select` —— 选择赋值

当你在同一个表达式上做分支判断（就像软件中的 `switch` 语句那样）时比较合适：

```vhdl
with mode select
  y <=
    a   when "00",
    b   when "01",
    c   when "10",
    'Z' when others;
```

所有分支都是基于同一个信号（`mode`）做比较，而 `when others` 是强制要求的，用来覆盖所有可能的位型。这种写法会综合成**平衡多路选择器** —— 没有任何分支享有特权。

## 应该选哪一个？

- **同一个信号，许多模式：** `with/select` 读起来就像真值表。用它。
- **不同信号，优先级逻辑：** 选 `when/else`，天然合适。
- **综合产物：** 在现代 FPGA 上两种写法会生成大致相同的门电路 —— 在源码层面选择更清晰的写法几乎总是正确的决定。

## 一个小陷阱

两种写法都要求 `y` 在**每一种**情形下都能被赋值。如果你忘了 `when/else` 末尾的 `else`，或者跳过了 `with/select` 的 `when others`，编译器会警告你 —— 而综合器可能会推导出一个锁存器（latch）来"记住"上一个值，这几乎永远不是你想要的。这和时序模块中"修复题"里要遇到的锁存器陷阱是同一个。

## 下一次出现

你将在本课之后的 3-to-8 译码器示例中使用 `with/select`，而后在交通灯 FSM 中大量使用 `when/else`。两者都是 VHDL 的基本功。
