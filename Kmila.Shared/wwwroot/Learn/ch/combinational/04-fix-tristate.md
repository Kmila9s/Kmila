# 修复:总是在驱动的三态缓冲器

三态缓冲器是一个可切换的输出。当输出使能(`oe`)信号为高时,它把数据透传到总线;当 `oe` 为低时,它**释放**总线 —— 驱动高阻态(`'Z'`),让别的设备可以发话。这是本单元里唯一一处让九值逻辑中的 `'Z'` 真正派上用场的地方。

## 哪里不对

打开示例,看主体:

```vhdl
y <= d when oe = '0' else 'Z';
```

把它念出来:“`y` 等于 `d`,**当 `oe` 是 0** 的时候,否则是 `'Z'`。”这是反的。你想要的是:使能为**高**时让缓冲器透传数据,为**低**时释放。

## 你的任务

- 在编辑器里打开示例。
- 改 `y <=` 赋值上的条件,让 `oe` 的意义正确:

```vhdl
y <= d when oe = '1' else 'Z';
```

- 跑仿真,在 Waveforms 标签页里确认:
  - `oe = '0'` 时,`y` 应该是 `'Z'`。
  - `oe = '1'` 时,`y` 应该跟着 `d`。

## 为什么这里 `'Z'` 很特别

`'Z'` 不是第三个逻辑*电平* —— 它意味着“我没在驱动”。在波形上 GTKWave 把它画成一条停在中间的线,既不高也不低。三态的全部意义,就是让一根导线可以有**好几个**潜在的驱动源,而任何时刻只有一个在起作用。这之所以安全,全因为 `std_logic` 是一个*可解析(resolved)*类型:当一个驱动源是 `'Z'` 而另一个驱动 `'0'` 或 `'1'` 时,解析会让强值胜出。如果每个驱动源都是 `'Z'`,这根线就悬空。

## 附加:留意 `'X'`

如果两个三态缓冲器同时以**不同的**值驱动同一条总线,真实电路会自己跟自己较劲并发热。解析函数把这种情况在波形上建模成 `'X'`(强未知)—— 这是一个明确的红旗,说明你的使能有重叠。搭一个小测试台,把你的两个缓冲器接到同一个 `y` 上,把两条 `oe` 都打开、给不同的 `d`,看总线变成 `'X'`。

## 为什么三态重要(以及它今天住在哪里)

三态缓冲器是多个驱动源共享同一根导线(一条总线)而不互相短路的办法。关于你实际要落地的硬件,有个重要的提醒:**FPGA 的逻辑纤维内部没有三态缓冲器** —— 综合会自动用多路选择器替换一条内部三态总线。三态只在 **I/O 焊盘(pad)**上幸存,而在那里它们正是双向引脚的工作方式:DDR 内存的数据线、I²C 的 `sda`,以及其它共享总线,都是靠一条 `oe` 来打开和关闭引脚驱动器的。那个双向焊盘用一个 `inout` 端口来建模:

```vhdl
io_pin <= drive_value when oe = '1' else 'Z';  -- 驱动或释放焊盘
read_value <= io_pin;                           -- 始终采样那里有什么
```

## 要点

- 一个三态在被使能时透传数据、在没被使能时驱动 `'Z'`(释放)—— 把 `oe` 的意义搞对。
- `'Z'` 意味着“没在驱动”,正是这一点让多个驱动源能共享一根可解析的 `std_logic` 导线。
- 两个活动的驱动源给出不同的值会解析成 `'X'` —— 一个你能在波形上看到的 bug。
- 在 FPGA 内部,三态会变成多路选择器;真正的三态住在双向引脚(`inout`)的 I/O 焊盘上。
