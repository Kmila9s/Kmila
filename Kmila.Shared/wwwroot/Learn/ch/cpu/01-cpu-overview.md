# CPU 如何执行一条指令

往任何 CPU 里看 —— 从最小的 8 位单片机到现代 GPU 着色器核心 —— 你都会发现同样的五级,做同样的五件事:

```mermaid
flowchart LR
    IF["IF<br/>取指"] --> ID["ID<br/>译码"] --> EX["EX<br/>执行"] --> MEM["MEM<br/>访存"] --> WB["WB<br/>写回"]
```

## 经典五级

**IF(取指)。** 从程序存储器里、按 Program Counter (PC) 的地址读下一条指令。PC 自增,让下一周期指向再下一条指令。

**ID(译码)。** 把指令字拆开。分成一个 **opcode**(干什么操作?)和**操作数字段**(用哪些寄存器?哪个立即数?)。

**EX(执行)。** 把操作数喂进 ALU。对 `ADD R0, R1`,EX 从寄存器堆里读 R0、R1,告诉 ALU "加",锁住结果。对 `JUMP addr`,EX 计算新的 PC。

**MEM(访存)。** 如果是 load 或 store,这一级跟数据存储器对话。寄存器到寄存器的指令在这一级是直通 —— 但这一级永远在,这样每条指令的流水线深度都一样。

**WB(写回)。** 结果最终落到它的目的地 —— 算术运算落寄存器,跳转落 PC,store 落到内存单元。

## 单周期、多周期、流水线

同样这五件事在硅上可以三种摆法:

**单周期。** 五级在一个时钟周期内组合执行。优:简单。缺:时钟要慢到让最长那条指令(通常是 load)在一个 tick 内穿过*所有东西*。MIPS 教学例子全是单周期。

**多周期。** 一级一周期。指令存在一个状态寄存器里,逐级前进。优:时钟比单周期快(每一级有自己的短关键路径)。缺:每条指令五拍。

**流水线。** 同时有五条指令在飞,各在不同的一级。优:每拍退出一条新指令,所以吞吐 ≈ 单周期但时钟快得多。缺:冒险(数据、控制、结构),计算机体系结构课后面整学期讲的就是这个。RISC-V 核、ARM Cortex-M、AMD Zen —— 都是流水线。

## 本课程里的 CPU 项目

你的第一颗 CPU 是**单周期**的,这样还能掌握。所有事情在一个时钟周期内组合发生:

- PC 寻址一颗 16 字节 ROM。
- 取到的字节既是 opcode nibble,又是立即数 nibble。
- 译码 + 执行 + 写回都在下一个时钟上升沿之前完成,上升沿锁住新的 PC 和新的 R0。

## 我们要实现的 ISA

四条指令,4 位 opcode + 4 位立即数:

| Opcode | 助记符        | 语义                          |
|--------|---------------|-------------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`        |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)`   |
| `0010` | `JUMP addr`   | `PC <= addr`                  |
| `1111` | `HALT`        | 把 PC 和 R0 冻住              |

一段你已经能手工跑的程序:

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## 你拿到了什么

一旦脚手架能跑,你就有了一台**可编程的机器**。改 ROM 里的字节 —— 就改了 CPU 跑的程序。这就是最基本的把戏:同样的硬件、不同的存储内容、不同的行为。

从这里你可以长大:

- 多加几个寄存器(R0..R3)。
- 加条件跳转(`JZ`、`JNZ`),让程序能分支。
- 从 RAM 模块加 load/store(重用 Memories 模块那个)。
- 把整条做成流水线。

从这台四指令机器到完整的 RV32I RISC-V 核还有很长一段路,但每一步都只是同一个模式的扩展,而你马上就要构造这个模式。
