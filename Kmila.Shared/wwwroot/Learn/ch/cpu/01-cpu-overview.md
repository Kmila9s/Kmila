# CPU 如何执行一条指令

往任何 CPU 里看——从最小的 8 位单片机到现代 GPU 的着色器核心——你都会发现同样的五级,做着同样的五件事:

```mermaid
flowchart LR
    IF["IF<br/>取指"] --> ID["ID<br/>译码"] --> EX["EX<br/>执行"] --> MEM["MEM<br/>访存"] --> WB["WB<br/>写回"]
```

## 经典的五级

**IF(取指)。**从程序存储器里、按 Program Counter(PC)里的地址读下一条指令。PC 自增,让下一个周期我们指向再下一条指令。

**ID(译码)。**把指令字拆开。分成一个 **opcode**(干什么操作?)和**操作数字段**(用哪些寄存器?哪个立即数?)。

**EX(执行)。**把操作数喂进 ALU。对一条 `ADD R0, R1` 指令,EX 从寄存器堆里读 R0 和 R1,告诉 ALU"加",并锁住结果。对一条 `JUMP addr` 指令,EX 算出新的 PC。

**MEM(访存)。**如果指令是 load 或 store,这一级就是你跟数据存储器对话的地方。对寄存器到寄存器的指令,这一级是直通——但这一级永远在,这样每条指令的流水线深度都一样。

**WB(写回)。**结果最终落到它的目的地——算术运算落寄存器,跳转落 PC,store 落到一个内存单元。

## 单周期、多周期、流水线

同样这五件事,在硅上可以有三种不同的摆法:

**单周期。**五级在一个时钟周期内组合地执行。优点:简单。缺点:时钟得慢到让最长那条指令(通常是 load)在一拍之内穿过*所有东西*。每一个简单的 MIPS 教学例子都是单周期的。

**多周期。**一级一个时钟周期。指令在逐级前进的过程中待在一个状态寄存器里。优点:时钟比单周期快(每一级都有自己那条短的关键路径)。缺点:每条指令五个周期。

**流水线。**同时有五条指令在飞,各在一个不同的级里。优点:每一拍退出一条新指令,所以吞吐 ≈ 单周期,但时钟快得多。缺点:冒险(数据、控制、结构),计算机体系结构课后面整学期讲的就是它。RISC-V 核、ARM Cortex-M、AMD Zen——全是流水线。

## RISC、CISC,以及为什么这几级这么干净

那五个利落的级不是偶然——它们是当指令集被设计得规整时你自然得到的东西。这就是 ESCOM 这门课所围绕的 **RISC**(精简指令集计算机)哲学:

- **定长指令**(每条指令的位数都一样),所以取指和译码都轻而易举。
- **load/store 架构**——只有专门的 load 和 store 指令碰内存;算术都在寄存器之间进行。这就是为什么 MEM 是一个干净的独立级。
- **大量通用寄存器**,这样编译器就把值留在寄存器堆里,而不是溢出到内存去。

**CISC**(复杂指令集计算机,例如 x86)押的是相反的宝:变长指令、一条指令里既读内存*又*计算的操作,以及几百种寻址方式。单条指令很强大,但要干净地做流水线就难多了。现代 x86 芯片其实会在内部把每条复杂指令拆成类似 RISC 的微操作。

还有一个值得点名的分野:**冯·诺依曼**机把程序和数据放在同一块存储器里(一条总线,简单,但代码和数据要争用它);**哈佛**机用分开的指令存储器和数据存储器,这正是让一个单周期或流水线核能在同一拍里既取一条指令*又*访问数据的东西。你马上要搭的这颗 CPU 实际上就是哈佛结构——一个 ROM 放代码,一条分开的通路放数据。

## 指令格式

译码之所以容易,只因为每条指令的各个字段都坐在固定的位置上。经典 RISC(MIPS 风格,ESCOM 采用的模型)有三种格式:

- **R 型**——寄存器到寄存器的 ALU 操作:`opcode | rs | rt | rd | shamt | funct`。两个源寄存器、一个目的寄存器、一个移位量,还有一个功能选择符。
- **I 型**——立即数 / load / store / 分支:`opcode | rs | rt | immediate`。那个 16 位立即数是一个常量或一个地址偏移。
- **J 型**——跳转:`opcode | address`。一个很大的地址字段,用来够到很远的目标。

下面那个玩具 ISA 是这个想法的一个双字段表亲:一个 4 位 opcode 加一个 4 位立即数。同样的原理,更小而已。

## 本课程里的 CPU 项目

你的第一颗 CPU 会是**单周期**的,好让它还掌控得住。一切都在一个时钟周期内组合地发生:

- PC 寻址一颗 16 字节的 ROM。
- 取到的字节既是 opcode nibble,又是立即数 nibble。
- 译码 + 执行 + 写回全都在下一个时钟上升沿之前完成,而上升沿锁住新的 PC 和新的 R0。

## 我们要实现的 ISA

四条指令,4 位 opcode + 4 位立即数:

| Opcode | 助记符        | 语义                        |
|--------|---------------|-----------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`      |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)` |
| `0010` | `JUMP addr`   | `PC <= addr`                |
| `1111` | `HALT`        | 把 PC 和 R0 冻住            |

一段你已经能手工跑的程序:

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## 你拿到了什么

一旦脚手架能跑,你就有了一台**可编程的机器**。改 ROM 里的字节——就改了 CPU 跑的程序。这就是最根本的把戏:同样的硬件、存储里不同的内容、不同的行为。

从这里你可以长大:

- 多加几个寄存器(R0..R3)。
- 加条件跳转(`JZ`、`JNZ`),让你的程序能分支。
- 从一个 RAM 模块加 load/store(重用 Memories 模块里那个)。
- 把整条东西做成流水线。

从这台四指令机器到一颗完整的 RV32I RISC-V 核,还有很长一段路,但每一步都只是你马上要搭的那个模式的更多展开而已。

## 这一切由谁来掌舵:控制单元

数据通路(PC、ROM、寄存器堆、ALU、存储器)是管道;**控制单元**是每个周期打开正确阀门的那个东西。它读 opcode 并驱动控制信号:用哪个 ALU 操作、这个周期寄存器堆是否写、存储器是读还是写、下一个 PC 从哪儿来。有两种搭法:

- **硬连线控制**——opcode 喂进组合逻辑(或一个微型状态机),直接产出那些信号。快,也是一颗干净 RISC 的自然选择。这就是你的脚手架用它那个对 opcode 的 `case` 所做的事。
- **微码控制**——每条指令是一小段存在微码 ROM 里的*微指令*程序,由它一步步把控制信号放出来。灵活,历史上也是 CISC 机器驯服其复杂度的方式,代价是速度。ESCOM 的教学大纲把两者都点了名(微指令、微码存储器),好让你能把它们区分开。

旁边还坐着**状态寄存器**——你的 ALU 产出的那些标志(零、进位、溢出、负)。条件分支不过就是控制单元测试其中某个标志,来决定下一个 PC。

## 要点

- 每一颗 CPU,无论大小,都跑同一个循环:取指、译码、执行、访存、写回。
- 这几级可以是单周期(简单,时钟慢)、多周期(时钟更快,每条好几个周期),或流水线(重叠执行,吞吐最高)。
- RISC 让指令定长、让访存只走 load/store,好让译码和流水线保持干净;CISC 把这个舍掉,换来单条指令的威力。
- 数据通路搬数据;控制单元——硬连线或微码——用 opcode 和状态标志决定什么搬到哪儿。
