# CPU 如何执行一条指令

深入任何一个 CPU —— 从一枚小小的 8 位单片机到现代 GPU 的着色器核心 —— 你都会发现相同的五个阶段，在做相同的五件事：

```mermaid
flowchart LR
    IF["IF<br/>取指"] --> ID["ID<br/>译码"] --> EX["EX<br/>执行"] --> MEM["MEM<br/>访存"] --> WB["WB<br/>写回"]
```

## 经典的五个阶段

**IF（Instruction Fetch，取指）。** 根据程序计数器（PC）中的地址，从程序存储器读取下一条指令。让 PC 递增，以便下个周期指向下一条指令。

**ID（Decode，译码）。** 拆开指令字。把它切分成**操作码**（做什么运算？）与**操作数字段**（用哪些寄存器？立即数是多少？）。

**EX（Execute，执行）。** 把操作数送入 ALU。对于 `ADD R0, R1` 这样的指令，EX 从寄存器堆里读出 R0 和 R1，告诉 ALU "加"，并锁存结果。对于 `JUMP addr`，EX 计算新的 PC。

**MEM（Memory，访存）。** 如果指令是 load 或 store，这是与数据存储器通信的阶段。对于寄存器到寄存器的指令，这个阶段是直通 —— 但它始终存在，以便每条指令具有相同的流水深度。

**WB（Writeback，写回）。** 结果最终落到目的地 —— 算术运算写到寄存器，跳转写到 PC，存储写到内存单元。

## 单周期、多周期与流水线

同样这五件事，在硅上可以有三种不同的排法：

**单周期。** 五个阶段全部在一个时钟周期内组合地执行。优点：简单。缺点：时钟必须慢到让最长的指令（通常是 load）在一个 tick 内传播通过**所有阶段**。每一个简单的 MIPS 教学样例都是单周期。

**多周期。** 每个时钟周期一个阶段。指令在穿越各阶段时驻留在一个状态寄存器里。优点：时钟比单周期更快（每个阶段都有自己较短的关键路径）。缺点：每条指令需要五个周期。

**流水线。** 同时有五条指令在流动，每条处于不同阶段。优点：每个时钟周期完成一条指令，因此吞吐率 ≈ 单周期但时钟快得多。缺点：冒险（数据冒险、控制冒险、结构冒险）—— 整个计算机体系结构课程后半段都是讲这个。RISC-V 核心、ARM Cortex-M、AMD Zen —— 全都是流水线。

## 本课程中的 CPU 项目

为了把复杂度控制住，你的第一个 CPU 是**单周期**的。一切都在一个时钟周期内组合地完成：

- PC 为一个 16 字节的 ROM 提供地址。
- 取出的字节既是操作码半字节，也是立即数半字节。
- 译码 + 执行 + 写回都在下一个上升沿之前完成，而该边沿捕获新的 PC 和新的 R0。

## 我们要实现的 ISA

四条指令，4 位操作码 + 4 位立即数：

| 操作码 | 助记符        | 语义                        |
|--------|---------------|-----------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`      |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)` |
| `0010` | `JUMP addr`   | `PC <= addr`                |
| `1111` | `HALT`        | 冻结 PC 和 R0               |

一个你已经可以手工执行的程序：

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## 这能给你什么

脚手架跑通后，你就有了一台**可编程机器**。改变 ROM 里的字节 —— 改变 CPU 运行的程序。这就是最根本的魔法：同样的硬件，不同的存储内容，不同的行为。

从这里可以继续长大：

- 加入更多寄存器（R0..R3）。
- 加入条件跳转（`JZ`、`JNZ`），让程序能分支。
- 从 RAM 模块（复用存储器模块里那个）加入 load/store。
- 把整个东西流水线化。

从这台 4 条指令的机器到一颗完整的 RV32I RISC-V 核心，路很长，但每一步都只是把你即将构建的同一种模式重复更多次而已。
