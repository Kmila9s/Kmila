# 示例:推断出的同步 ROM

每个 FPGA 都有 **block RAM**(BRAM)——专用的存储块,当综合器在你的代码里认出一个 ROM 或 RAM 模式时就会用上它们。你不去实例化厂商原语;你写普通的 VHDL,只要写成工具认得的形状就行。"推断"就是这种识别的名字:工具读你的数组加进程,然后*推断*出你的意思是一块存储器。

这个示例是那个可移植的、教科书式的 ROM 写法。每一个正经的综合器(Xilinx/AMD Vivado、Intel/Altera Quartus、Lattice Radiant、开源的 Yosys)都会认出它,并自动分配 BRAM。

## 这个写法

```vhdl
type rom_t is array(0 to 15) of std_logic_vector(7 downto 0);
constant ROM : rom_t := (
  x"00", x"01", x"04", x"09", x"10", x"19", x"24", x"31",
  x"40", x"51", x"64", x"79", x"90", x"A9", x"C4", x"E1"
);

process(clk)
begin
  if rising_edge(clk) then
    data <= ROM(to_integer(unsigned(addr)));
  end if;
end process;
```

三件事让它成为一个 BRAM 友好的 ROM:

1. **存储是一个常量**(`constant ROM : rom_t := (...)`)。数据在综合时就固定了。
2. **读取是时钟驱动的。**组合式的 ROM 读取只能映射到 LUT——对一个只有 16 项的小 ROM 没问题,但再大一点就需要这种时钟读取的写法,综合器才会去分配 BRAM。
3. **`addr` 纯粹当作一个索引。**在 `addr` 和存储器查表之间没有昂贵的组合逻辑。

## 组合读 vs 同步读,以及读延迟

时钟读取是全部关键所在。把读取写成一句普通的并发赋值——

```vhdl
data <= ROM(to_integer(unsigned(addr)));   -- 组合:分布式 ROM(LUT)
```

——工具就会用 LUT 来搭这个 ROM("分布式"存储器)。那是零读延迟,但会耗掉通用逻辑,而且不能扩展:几 KB 的 LUT-ROM 就能淹没一颗小器件。把读取寄存起来(上面那个 `process`),工具就能把整张表塞进一块 block RAM,那要密集得多。

寄存读取的代价是**一个周期的延迟**:你在一个沿上给出 `addr`,`data` 在*下一个*沿才出现。这不是 bug——它是同步存储器的定义性特征,而且 BRAM 内部的那个输出寄存器,正是让设计在高时钟频率下满足时序的东西。许多 FPGA 还提供第二个可选的输出寄存器,以第二个周期的延迟为代价换取更好的时序。

## 地址位宽必须和深度匹配

`to_integer(unsigned(addr))` 绝不能索引到数组之外。对一个 16 项的 ROM,`addr` 应该正好是 4 位;更宽的 `addr` 会产生一个越界的索引,在仿真里出错,综合后行为不可预测。保持 `2**addr'length = DEPTH`,或者对索引做限幅/保护。把深度、位宽和地址大小绑在一起,整件事就始终一致。

## 为什么是这些内容?

示例 ROM 存的是 `n²`(`n = 0..15`)。用在一个查表式的平方单元上很有用——当你只需要小操作数时,它比一个完整的乘法器更快。你也可以存:

- 一张正弦波表(用于 DDS 信号发生器)
- CRC 多项式
- 协议查表
- 字符字体

一个 ROM 其实就是一张冻结进硅片的真值表:地址比特的任何组合函数,都可以预先算好并存起来,用存储换逻辑。

## 示例做了什么

仿真把 `addr` 驱动过 5 个特定值:0、1、4、8、15。在时钟沿之后,`data` 显示对应的 ROM 项,晚一个周期(这就是同步 ROM 的读延迟——你要地址,你在**下一个**时钟才拿到数据)。

## 轮到你

- **把它参数化。**把固定的 16 项大小换成 `generic (DEPTH : integer := 16; WIDTH : integer := 8)`,并把 `addr` 定成 `std_logic_vector(log2(DEPTH)-1 downto 0)`。其余代码应该照常工作。
- **从文件读内容。**真实项目通过一个初始化函数或一个单独的常量 package 来加载 ROM 内容。试试让 VHDL 去读一个十六进制值的文本文件(`std.textio` + `hread`),放在一个返回数组的 impure 函数里——大多数工具会在 elaboration 阶段运行它,并把结果烤进 BRAM。
- **加第二个读端口。**用于单周期 CPU 里的指令/数据存储器之类的东西。你会在课程后面的 CPU 项目里看到这个模式。

## 与课程的联系

这是第四单元*存储器*:ROM 家族(ROM、PROM、EPROM、EEPROM、Flash),具体来说是*用硬件描述语言做数组处理与存储器设计*。那个 `type … array … of` 常量正是这个单元要求的"数组处理";而文件初始化那个练习,则向前伸进了第五单元对文件、函数和 package 的使用。

## 要点

- 推断的意思,就是把存储器写成工具认得的形状——不需要厂商原语。
- 在一个时钟进程里读取一个**常量**数组,就是那个可移植的同步 ROM 写法;它映射到 block RAM。
- 时钟读取 = 一个周期的延迟加密集的 BRAM;组合读取 = 零延迟,但耗 LUT,无法扩展。
- 让地址位宽和深度匹配,这样索引就永远不会跑出数组的尽头。
