# 项目:UART 发送器

UART(通用异步收发器)是大多数嵌入式设计者构建的第一个真实协议。它点对点、全双工,只需要三根线(TX、RX、GND)。每个 FTDI USB-串口适配器、每条 Arduino 的 `Serial.print`、每个老旧终端,底层都是一个 UART。

这个项目构建**发送**端。等你做完这个,接收端是一个绝佳的下一个项目。

## 异步:没有一根时钟线

UART 里的那个"A"(Asynchronous)才是整个挑战所在。和 SPI 或 I2C 不同,两端**不共享时钟线**。接收端必须从数据本身里把时序恢复出来。这只有在两端事先就对**波特率**(每秒多少位)和**帧格式**达成一致时才行得通。其中任一个弄错,你收到的就是乱码——波特率不匹配的经典症状。

在 ESCOM 这门课里,这归在 RS-232 标准下。有两样人们常混为一谈的东西值得分清:**UART** 是把字节串行化的那段数字逻辑(就是你在这里构建的,工作在 0 V / 3.3 V 的逻辑电平上),而 **RS-232** 是把那些电平挪到大约 ±12 V、并以*反相*极性去驱动一根电缆的那个电气标准。一个 MAX232 式的线路驱动器坐在你的 UART 引脚和一个真实的 DB-9 连接器之间。你的 VHDL 永远只跟那个干净的逻辑电平一侧打交道。

## 帧格式(无校验、8 位数据、1 位停止)

```
  Idle  Start   Bit0  Bit1  Bit2  Bit3  Bit4  Bit5  Bit6  Bit7   Stop   Idle
  ────┐      ┌───── ... ─────────────────────────────── ... ─────┐──────
      │      │
      └──────┘
    线路平时为高('1');起始位是一个下降沿。
```

这就是"8N1":**8** 个数据位、**N**o 无校验、**1** 个停止位——每个字节在线上是 10 位。要紧的规则:

- **Idle**(空闲)是高。一根断了或没接的线读出来是空闲,而不是一串零。
- **Start**(起始)位是低。它的下降沿是接收端唯一拿得到的时序参考。
- **Data**(数据)**先发 LSB**——第 0 位在第 7 位之前。
- **Stop**(停止)位是高,这也保证了下一帧总有一个新鲜的下降沿可用。

每个 bit 在 `tx` 上保持恰好 `clk_freq / baud` 个时钟周期。对一个 50 MHz 时钟和 115 200 波特,那就是 50 000 000 / 115 200 ≈ 每位 434 个周期。

## 你要做的

1. 构建一个时钟计数器,每 ~434 个周期产生一个单周期的 `baud_tick`。
2. 当 `send = '1'` 时,把 `data` 锁进一个 10 位移位寄存器:`{ stop_bit, data[7..0], start_bit } = 1 & data & 0`。驱动 `busy <= '1'`。
3. 每个 `baud_tick` 把寄存器右移(这样起始位先出去,然后是数据的 LSB 到 MSB,最后是停止位)。
4. 第 10 个 tick 之后,把 `busy` 拉低,`tx` 回到空闲的高电平。

## 脚手架

实体和空闲状态已经给你;`tx` 默认高,`busy` 默认低。介于这两个默认之间的一切,都归你负责。

```vhdl
architecture rtl of uart_tx is
  signal tx_reg : std_logic := '1';
begin
  tx   <= tx_reg;
  busy <= '0';       -- TODO
end architecture rtl;
```

## 建议的结构

两个计数器 + 一个移位寄存器:

```vhdl
signal clk_count  : unsigned(9 downto 0);   -- 0..434
signal bit_count  : unsigned(3 downto 0);   -- 0..9
signal shift_reg  : std_logic_vector(9 downto 0);
signal sending    : std_logic := '0';
```

- 当 `send = '1'` 且 `sending = '0'`:
  - 加载 `shift_reg <= '1' & data & '0';`
  - `sending <= '1';  clk_count <= 0;  bit_count <= 0;`
- 当 `sending = '1'`:
  - `clk_count <= clk_count + 1;`
  - 如果 `clk_count = BAUD_PERIOD - 1`:
    - `tx_reg <= shift_reg(0);`
    - `shift_reg <= '1' & shift_reg(9 downto 1);` —— 右移,顶端用空闲值补齐
    - `bit_count <= bit_count + 1;`
    - `clk_count <= 0;`
  - 如果 `bit_count = 10`:
    - `sending <= '0';`

把 `BAUD_PERIOD` 做成一个 generic,这样你仿真时可以把它调小(例如 5 周期/位),而同一段逻辑在硬件上仍能跑满速。

## 你能容忍多大的时序误差

因为没有共享时钟,接收端在每个 bit 中心附近采样,并在一帧里一点点漂移。在 10 个 bit 周期上,累积的误差必须保持在半个 bit 以内,所以每一端的波特率误差得保持在大约 ±2–3% 以内。整数分频器很少刚好落准:在 50 MHz 下,434 周期/位给出 115 207 波特——误差 0.006%,完全安全。一个别扭的时钟可能凑整得很糟,这就是为什么许多真实的 UART 加了一个小数分频器。接收端靠以波特率的 16× **过采样**来挣得余量:找到起始边沿,然后在计数 8(bit 中心)处采样,之后每 16 个 tick 采一次。

## 要测什么

用 `data = "01001000"`(ASCII `'H'`)驱动 `send = '1'`。帧完成之后,`tx` 波形应当显示恰好 10 个 bit 周期的活动:

1. 起始(低)
2. data 的第 0 位(也就是 LSB:`0`)
3. `0`
4. `0`
5. `1`
6. `0`
7. `0`
8. `1`
9. `0`(MSB)
10. 停止(高)

然后回到空闲的高。放大到 Waveforms 标签页,逐位验证这个模式。

## 常见的坑

- **位序弄反。**先发 MSB 是最常见的那一个 bug。脚手架里的 `'1' & data & '0'` 加上一个右移,白送就是 LSB 优先——别去"修"它。
- **位计数差一。**8N1 是 *10* 个 tick,不是 8。忘了起始位或停止位,帧就被截断。
- **帧中途被重新触发。**只在 `sending = '0'` 时才理会 `send`,否则第二个请求会破坏正在飞的那一帧。这就是 `busy` 的用处。
- **波特率不匹配。**如果接收端显示的字节数对、但值是乱的,先怀疑分频器,再怀疑逻辑。

## 再进一步

- 加一个 **FIFO**,这样你可以排队好几个字节;`send` 就变成了"push"。
- 构建 **RX** 端:16× 过采样,找到起始边沿,在 bit 中心采样。
- 把帧参数化:校验、7 位 vs 8 位数据、1 位 vs 2 位停止位。

## 要点

- UART 是**异步的**:没有时钟线,所以两端必须事先就波特率和帧格式达成一致。
- 8N1 在线上是 **10 位**——空闲高、起始低、8 个数据位**先发 LSB**、停止高。
- 一个 bit 持续 `clk_freq / baud` 个周期;一个单周期的 `baud_tick` 为移位寄存器打拍。
- 把每一端的波特率误差控制在 ~2% 以内;RX 端靠**过采样并在 bit 中心采样**来买余量。
- **UART** 是逻辑;**RS-232** 是线路驱动器加在上面的那层 ±12 V 电气层。
