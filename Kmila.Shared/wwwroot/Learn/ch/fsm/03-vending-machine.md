# 项目:投币式自动售货机

这是你第一个像样的项目。规格是定死的,起步代码把管线给你搭好,你的活儿是把补完它的逻辑写出来。

## 你要构建什么

一个 FSM,跟踪顾客投入的金额,当总额累计到 25¢ 时就出货(一个单一的输出脉冲 `dispense`)。输入是:

- `nickel` —— 1 周期脉冲,意思是"刚刚掉进来一枚 5¢ 硬币"
- `dime`   —— 1 周期脉冲,意思是"刚刚掉进来一枚 10¢ 硬币"
- `clk`、`reset`

输出是:

- `dispense` —— 当你累计到 ≥ 25¢ 时,拉高恰好一个时钟周期
- `change`   —— 如果总额**超过**了 25¢,就和 `dispense` 同时拉高一个周期(这样机器才知道要找零)

## 两种建模方式

自动售货机是经典的 FSM,有两种实在的描述办法:

- **显式状态。**把每个可达的总额都枚举出来——`S0, S5, S10, S15, S20`——并为每种硬币画一条转移。这是教科书的做法,对一个小的硬币集合你手工也是这么做的。它让状态图一目了然,但一旦你加更多硬币或抬高价格,状态数就会爆炸。
- **累加器(数据通路)风格。**把总额存在一个小寄存器里,再和价格比较。行数更少,能扩展到任意价格,也是起步代码采用的形状。你可以把 `total` 寄存器当作状态,把比较器当作次态逻辑。

无论哪种方式,`dispense` 都依赖*这个*周期到来的硬币,所以它表现得像一个 **Mealy** 输出——它在销售条件成立的同一个周期里就作出反应,而不是等一个周期。

## 起步代码给了你什么

实体和 `total` 累加器都接好了。每个 `nickel` 脉冲加 5,每个 `dime` 脉冲加 10。但起步代码始终驱动 `dispense = '0'` 和 `change = '0'`。**这就是你需要改的地方。**

```vhdl
process(clk, reset)
begin
  if reset = '1' then
    total <= (others => '0');
  elsif rising_edge(clk) then
    if    nickel = '1' then total <= total + 5;
    elsif dime   = '1' then total <= total + 10;
    end if;
  end if;
end process;

dispense <= '0';  -- TODO
change   <= '0';  -- TODO
```

## 建议的做法

1. **检测销售条件。**在每个上升沿,加上当前这枚硬币之后,判断 `total >= 25`。(注意:你要算的是*新的*总额,不是上一个周期的那个。)
2. **让 `dispense` 拉高恰好一个周期。**诀窍:当你检测到销售时,把脉冲置起,并把 `total` 清回零。因为 `total` 在同一个沿上被清掉,下一个周期条件就不成立了,所以脉冲天然就只有一个周期宽。
3. **计算 `change`。**如果销售那一刻的总额 > 25,就也把 `change` 拉起来。

把"下一拍总额"算成进程内部的一个 `variable`,这样判断用的就是最新的值,而不是上一个周期的寄存器值:

```vhdl
process(clk, reset)
  variable next_total : unsigned(5 downto 0);
begin
  if reset = '1' then
    total    <= (others => '0');
    dispense <= '0';
    change   <= '0';
  elsif rising_edge(clk) then
    next_total := total;
    if    nickel = '1' then next_total := total + 5;
    elsif dime   = '1' then next_total := total + 10;
    end if;

    if next_total >= 25 then
      dispense <= '1';
      if next_total > 25 then change <= '1'; else change <= '0'; end if;
      total    <= (others => '0');
    else
      dispense <= '0';
      change   <= '0';
      total    <= next_total;
    end if;
  end if;
end process;
```

有两点要留意。`variable` 用 `:=` 赋值,并在进程内部**立即**更新,这正是为什么 `next_total` 已经把这个周期的硬币算进去了——换成信号(`<=`)要等进程挂起才会更新。还有,因为 `dispense`、`change` 和 `total` 全都在时钟进程里被驱动,它们都被**寄存**了——脉冲和时钟沿对齐,不会出毛刺。

## 要当心

- **位宽。**`total + 10` 在复位触发前可以到 30,所以寄存器至少要 6 位——`unsigned(5 downto 0)` 装得下 0–63,还绰绰有余。向量太窄会悄悄回绕。
- **两种硬币同时来。**`if … elsif` 意味着 `nickel` 和 `dime` 同时出现时只会算 nickel。你得决定这对你的规格是可接受,还是一个错误。
- **忘了清 `total`。**如果你拉起了 `dispense` 却没把累加器清零,机器就会每个周期"卖"一次,直到更多硬币改变总额为止。在销售沿清零,正是让脉冲只有一个周期宽的关键。

## 验收标准

| 投币序列             | 期望行为                       |
|----------------------|--------------------------------|
| 5 个 nickel          | `dispense=1, change=0`         |
| 2 个 dime + 1 nickel | `dispense=1, change=0`         |
| 3 个 dime(= 30¢)    | `dispense=1, change=1`         |
| 2 个 nickel + 1 dime | 不出货(只有 20¢)             |

## 再进一步

- 加一个**退币**按钮,把 `total` 清零但不出货。
- 支持一枚 **quarter**(25¢)硬币——应该立刻出货。
- 用一个独立的 8 位计数器记录售出的件数,并作为一个输出让外界看到。真实的售货机就是这样向上游汇报的。

## 与课程的联系

这是第二单元*自动机与硬件描述语言的应用*:一台由行为规格定义、再用 HDL 描述的确定性时序机。那个累加器加比较器的形状,也是对第五单元的一个温和铺垫——在那里,你会把一个设计显式地拆成一条**数据通路**(`total` 寄存器和加法器)和一个驱动它的**控制**自动机。

## 要点

- 自动售货机是一个 FSM;为了清晰,用显式状态来建模;为了可扩展,用一个累加器寄存器。
- 用一个 `variable`(`:=`)来算"下一拍总额",这样销售判断就包含了刚到的那枚硬币。
- 在销售沿清零累加器,就能做出一个单周期脉冲——寄存的输出让脉冲保持干净。
- 按你能到达的最大值去给向量定宽,并提前决定同时出现的输入该怎么处理。
