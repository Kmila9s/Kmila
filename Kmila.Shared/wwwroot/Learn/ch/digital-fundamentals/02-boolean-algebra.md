# 布尔代数以及你真正会用到的几条定律

布尔代数是关于 true/false 值以及可以对它们进行的运算的数学。每一个数字电路 —— 从单个门到上百万晶体管的 CPU —— 最终都是一个布尔表达式。

好消息：你只需要记住寥寥几个恒等式。有了它们，几乎任何表达式你都能手工化简。

## 三种基本运算

| 运算 | 符号（数学） | 符号（VHDL） | 读作 |
|------|--------------|--------------|------|
| AND  | · 或并列书写 | `and`        | "A 与 B" |
| OR   | +            | `or`         | "A 或 B" |
| NOT  | 上划线（`Ā`）| `not`        | "非 A"   |

二元运算符的真值表：

```
 A  B  │  A·B   A+B
──────┼────────────
 0  0  │   0     0
 0  1  │   0     1
 1  0  │   0     1
 1  1  │   1     1
```

## 你真正会用的恒等式

**交换律** —— 顺序无关：

```
A · B = B · A
A + B = B + A
```

**结合律** —— 分组无关：

```
(A · B) · C = A · (B · C)
(A + B) + C = A + (B + C)
```

**分配律** —— OR 那一条看着有点怪：

```
A · (B + C) = A·B + A·C
A + (B · C) = (A + B) · (A + C)   ← 对，真的
```

**同一律与吞并律**：

```
A + 0 = A      A · 1 = A
A + 1 = 1      A · 0 = 0
```

**互补律**：

```
A + Ā = 1      A · Ā = 0
```

**德摩根定律** —— 数字设计中最有用的两条改写规则：

```
not(A · B) = Ā + B̄
not(A + B) = Ā · B̄
```

德摩根让你能把 NAND 变成"两个非的或"，或把 NOR 变成"两个非的与"，或消掉冗长的非号。每一个 FPGA 工具链在优化时都在不停地使用它们。

## 一个化简的演算

从：

```
Y = A·B + A·B̄·C + A·B̄·C̄
```

把 `A` 提出来：

```
Y = A · (B + B̄·C + B̄·C̄)
```

在内部把 `B̄` 提出来：

```
Y = A · (B + B̄ · (C + C̄))
```

`C + C̄ = 1`（互补律），所以：

```
Y = A · (B + B̄ · 1)
  = A · (B + B̄)
  = A · 1
  = A
```

四项、五次 AND-OR 运算坍缩成一根线。这正是综合器在后台替你做的工作 —— 但亲手理解能让你在读别人的网表时更锐利。

## 关键要点

- AND / OR / NOT 就够了。NAND 和 NOR 只是在 AND/OR 后面粘了个 NOT。
- 德摩根是瑞士军刀 —— 学会在两个方向上都能识别出来。
- 当一个子表达式通过互补律变成 `1` 时，整个积项都会化简。
