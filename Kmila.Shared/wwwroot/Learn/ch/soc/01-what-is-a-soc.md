# 什么是片上系统?

你前面那条线里的 8 位 CPU 是独立运行的。它会算,但它不和外界对话。**片上系统(System-on-Chip)**是上一档的体量:一个 CPU 加上一把外设,再加上让它们彼此对话的那套结构,全都在同一颗硅片上。

这正是《片上系统》这门课的整个前提——不是把一个处理器、分开的存储芯片和分开的 I/O 芯片在一块板子上连起来,而是把处理器、它的存储器和它的外设集成进一个器件,然后给成品编程。

## 三块必备的零件

每一个 SoC,从扩展过的 Kmila CPU 到一颗 500 万美元的 Apple A 系列,归根结底都是:

1. **一个或多个处理单元**——CPU、DSP、GPU、加速器。
2. **存储器**——片上 SRAM、block RAM,有时还有片外 DDR。
3. **一套互连**——让 (1) 能和 (2) 以及外设对话的那些线 + 仲裁。

互连是那个不再"只是 RTL"、开始带上体系结构味道的部分。它规定谁能在什么时候说话、最多能有多少笔交易同时在飞,以及任意一次给定的请求能多快完成。

## 处理单元:RISC 与哈佛

你会遇到的大多数 SoC 核——PIC、AVR、ARM Cortex-M、RISC-V——都是 **RISC**(精简指令集计算机)。RISC 意味着一小套简单、定长的指令,每条只干一件事,所以译码和执行它们的硬件保持小而快。代价是复杂操作要用好几条指令,而不是一条。

那些核通常是**哈佛**架构:程序存储器和数据存储器坐在*分开的*总线上。因为两条总线相互独立,核可以在读或写一个数据操作数的同时去取下一条指令——是一条共享总线存储带宽的两倍。一个不错的副作用:指令字的宽度不必和数据字的宽度一样。举个例子,一颗 PIC 中档核跑的是 8 位数据但 14 位指令,所以每条指令都正好装进一个字。

(一台纯粹的**冯·诺依曼**机把代码和数据共用一条总线——更简单,但取代码和取数据会争用它。8051 是一个"改良哈佛"的折中。)

## 流水线

一个核通过重叠工作来每秒完成更多指令。最简单的形式是一个两级**流水线**:在指令 *N* 执行的同时,核已经在取指令 *N+1*。

```
  cycle:   1        2        3        4
  fetch:  I1       I2       I3       I4
  exec:            I1       I2       I3
```

麻烦在于**分支**。当一个 `GOTO`、`CALL` 或 `RETURN` 改变了程序计数器时,排在它后面已经取好的那条指令就是错的,必须扔掉——流水线*冲刷(flush)*并重新填满,花掉一个周期。这就是为什么紧凑的循环和跳转密集的代码,会比直线代码跑得稍慢一点。

## 程序存储器、数据存储器,以及编程模型

ESCOM 这个单元把存储映射拆成两种角色:

- **程序存储器**存放你的指令(常常是 flash/ROM)。非易失,所以器件每次上电都启动同一个程序。
- **数据存储器**存放变量、栈和 I/O 寄存器(SRAM)。易失,复位时清空。

叠在上面的是**编程模型**:程序员真正看得见的那些寄存器和地址映射。它定义了通用寄存器、特殊功能寄存器(状态标志、程序计数器、栈指针),以及——对一个 SoC 至关重要的——那些**内存映射的外设寄存器**。在一个内存映射的设计里,一个外设看起来就是几个地址:往一个地址写一个字节,UART 就发出去;读另一个地址,你就拿到 ADC 的结果。CPU 从不为每个外设学一条新指令;它只是做 load 和 store。

## 常见的互连协议

业界在那套 load/store 结构上收敛到了寥寥几个标准:

| 协议             | 厂商      | 你会在哪儿见到它                                 |
|------------------|-----------|--------------------------------------------------|
| AXI4 / AXI4-Lite | ARM       | RISC-V 核、Xilinx PS/PL 边界、大多数新 IP         |
| AHB / APB        | ARM       | 老的 ARM 核、低速外设                             |
| Avalon MM / ST   | Intel     | NIOS-II、Qsys 生成的 SoC                          |
| Wishbone         | OpenCores | OpenRISC、许多开源 IP 核                          |

它们最终都归结为同样的几条道:一条**地址通道**、一条**写数据通道**,和一条**读数据通道**。变化在于握手协议、乱序支持,以及 burst 语义。

## AXI4-Lite 究竟是什么

AXI 家族里最简单的成员。把 burst、乱序和 QoS 都剥掉,你得到五条独立的通道,每条都有一个 `valid`/`ready` 握手:

```
  AW  (写地址)
  W   (写数据)
  B   (写响应)
  AR  (读地址)
  R   (读数据)
```

每次传输都是一拍。当对端不 `ready` 时,每条通道都停住。就这些——而这恰恰正是为什么它是那个适合你亲手搭的大小。

## Kmila 的课程计划

后面的课程会从零搭一个 AXI4-Lite 寄存器接口,然后把它接在你那颗 8 位 CPU 和一个内存映射的 UART 之间,好让 CPU 通过往一个地址写就能"打印"。这给了你一个思维模型,去理解每一颗现代 SoC 内部到底在发生什么,而且体量小到你脑子里真的装得下。

## 要点

- 一个 SoC = 处理单元 + 存储器 + 一套互连,全在一颗硅片上。
- 大多数 SoC 核是带**哈佛**拆分的 **RISC**,所以代码和数据在分开的总线上同时搬动。
- 一条短的**流水线**重叠取指和执行;**分支会冲刷它**。
- 程序存储器是非易失的代码;数据存储器是易失的 RAM;**编程模型**是程序员看得见的那套寄存器与地址映射。
- 外设是**内存映射的**——CPU 用普通的 load 和 store、经由像 AXI4-Lite 这样的标准互连去够到它们。
