# 项目：带标志位的 8 位 ALU

**算术逻辑单元**（Arithmetic Logic Unit）是任何 CPU 跳动的心脏。给它两个操作数和一个操作码，它就会返回一个结果以及若干描述运算情况的标志位（是否溢出？结果是否为零？等等）。

## 你要构建的内容

一个 8 位 ALU，支持如下运算：

| 操作码  | 名称    | 公式                       |
|---------|---------|----------------------------|
| `000`   | ADD     | `y = a + b`               |
| `001`   | SUB     | `y = a - b`               |
| `010`   | AND     | `y = a and b`             |
| `011`   | OR      | `y = a or  b`             |
| `100`   | XOR     | `y = a xor b`             |
| `101`   | SHL     | `y = a 左移一位`          |
| `110`   | SHR     | `y = a 右移一位`          |
| `111`   | PASS_A  | `y = a`（直通）            |

另外还有两个标志输出：

- `zero` —— 当 `y` 全为零时为高电平
- `carry` —— 来自 ADD/SUB 的进位输出；其余情况驱动为 `'0'`

## 脚手架给你的部分

初始代码声明了 entity、`result` 和 `cout` 信号，以及一个已经处理好 ADD 与 SUB 的 `process(op, a, b)` 框架。你的任务是填写 `case` 语句其余的六个分支。

## 提示

- **AND / OR / XOR** 各自只需要一行 —— 直接赋位运算结果即可：

  ```vhdl
  when "010" => result <= a and b;
  ```

- **SHL** 与 **SHR** 用 `'0'` 填充：

  ```vhdl
  when "101" => result <= a(6 downto 0) & '0';
  when "110" => result <= '0' & a(7 downto 1);
  ```

- **PASS_A** 只需要把 `a` 复制到 `result`。

记得对逻辑运算分支驱动 `cout <= '0'` —— 你已经在 process 顶部做了一次默认赋值，也就是说没有显式覆盖它的分支会继承该默认值。这很方便，但意味着当某个分支**确实**需要非零进位时，你必须显式赋值。

## 验收标准

使用配套配置中提供的激励：

| 时刻 | op    | a          | b          | 期望的 `y`   | `carry` | `zero` |
|------|-------|------------|------------|--------------|---------|--------|
|  0   | `000` | `00001111` | `00000101` | `00010100`   | `0`     | `0`    |
| 20   | `001` | `00001111` | `00001111` | `00000000`   | `0`     | `1`    |
| 40   | `010` | `00001111` | `00001111` | `00001111`   | `0`     | `0`    |
| 60   | `101` | `10110000` | n/a        | `01100000`   | `0`     | `0`    |
| 80   | `111` | `10110000` | n/a        | `10110000`   | `0`     | `0`    |

## 进阶

- 添加一个 **signed** 标志（对二进制补码 SUB 为负数时置位）。
- 添加一个 **rotate** 操作码 —— 与 SHL 相同，但最高位回绕到第 0 位。
- 添加一个 **multiply** 操作码，在两个独立的输出端口上产生 16 位结果。大多数小型 FPGA 有专用的 DSP 模块来完成这件事 —— 重新综合时留意资源使用率。

这个 ALU 是专家级 CPU 项目的一块直接的构建砖 —— 把设计做干净些，后面你会把它接进去。
