# 项目:带标志位的 8 位 ALU

**算术逻辑单元**(ALU)是任何 CPU 跳动的心脏。给它两个操作数和一个 opcode;它就返回给你一个结果,外加一把描述刚才发生了什么的标志位(溢出了吗?结果是零吗?等等)。

## 你要构建什么

一个 8 位 ALU,支持下列操作:

| Opcode | 名称    | 公式                      |
|--------|---------|---------------------------|
| `000`  | ADD     | `y = a + b`               |
| `001`  | SUB     | `y = a - b`               |
| `010`  | AND     | `y = a and b`             |
| `011`  | OR      | `y = a or  b`             |
| `100`  | XOR     | `y = a xor b`             |
| `101`  | SHL     | `y = a 左移 1 位`          |
| `110`  | SHR     | `y = a 右移 1 位`          |
| `111`  | PASS_A  | `y = a`(直通)            |

外加两个标志位输出:

- `zero` —— 当 `y` 全是零时为高
- `carry` —— ADD/SUB 的进位输出;其它操作一律驱动 `'0'`

在 ESCOM《计算机体系结构》课里,这是 3.1 节,也是那颗单周期 RISC 处理器的第一个功能块。现在把它干干净净地搭好,后面你就能直接把它插进数据通路里。

## 底下的加法器

ADD 和 SUB 看起来就是一行 VHDL(`a + b`),但综合器为那个 `+` 搭出来的硬件,才是有意思的工程所在。课程要求你对比两种经典结构。

**行波进位加法器(Ripple-carry)。**把八个全加器串起来,把每一级的进位输出喂进下一级的进位输入。它小巧又直白,但进位得从第 0 位一路*行波*到第 7 位,最高那位的和才有效——所以最坏情况延迟随字长线性增长。对一个 8 位加法器,那就是八个全加器延迟首尾相接叠在一起。

**超前进位加法器(CLA)。**与其等进位一路波过去,不如直接从输入算出每一位的进位。为每一位定义两个信号:

```
generate:  g(i) = a(i) and b(i)      -- 这一位自己就产生一个进位
propagate: p(i) = a(i) xor b(i)      -- 这一位把一个进来的进位传递下去
```

那么每个进位就是 `c(i+1) = g(i) or (p(i) and c(i))`,展开之后,所有进位就是并行产生的,而不是一个接一个。延迟变得大致与字长无关,代价是更多的门。这就是教学大纲里拿来和串联的"级联进位"行波设计相对比的"超前进位"。

对于这个项目,你不必手工搭其中任何一个——写 `a + b` 就能让 FPGA 工具去挑一条优化过的进位链(Artix-7 的 fabric 甚至有专门的快速进位逻辑)。重点是去*理解*那个 `+` 代表的是什么权衡:面积对速度。

## 把标志位弄对

标志位是初学者悄悄丢分的地方,因为**进位**和**溢出**是两码事:

- **进位(C)**是从一次*无符号*加法顶上掉出来的那一位。它是 `a + b` 的第 9 位。
- **溢出(V)**表示一个*有符号*(二补码)结果再也装不进 8 位了。干净的规则是:`V = carry_into_MSB xor carry_out_of_MSB`。等价地说,如果两个同号的操作数产生了一个异号的结果,就发生了溢出。

一个一次性搞定两者的利落 VHDL 技巧,是在一个 9 位的空间里做加法:

```vhdl
signal ext : unsigned(8 downto 0);
...
ext   <= ('0' & unsigned(a)) + ('0' & unsigned(b));  -- 9 位加法
result <= std_logic_vector(ext(7 downto 0));
cout   <= ext(8);                                     -- 进位标志
```

对 SUB 来说,记住在二补码里减法就是 `a + (not b) + 1`,所以 `15 - 15` 内部会产生一个为 `1` 的进位输出,哪怕结果是零——这正是为什么许多 ISA 把减法的进位当作一个*借位*来处理(C = not borrow)。让你的约定和配套测试台所期望的那个保持一致。

## 脚手架给了你什么

起步代码声明了实体、`result` 和 `cout` 信号,以及一个已经处理好 ADD 和 SUB 的 `process(op, a, b)` 外壳。你的活儿是把 `case` 语句里另外六个分支填上。

## 提示

- 对 **AND / OR / XOR**,各一行就够——直接赋值按位结果:

  ```vhdl
  when "010" => result <= a and b;
  ```

- 对 **SHL** 和 **SHR**,用 `'0'` 补位:

  ```vhdl
  when "101" => result <= a(6 downto 0) & '0';
  when "110" => result <= '0' & a(7 downto 1);
  ```

- 对 **PASS_A**,直接把 `a` 复制给 `result`。

记得对逻辑操作要驱动 `cout <= '0'`——你已经在进程顶部做过一次了,这意味着任何没有覆盖它的分支都会继承那个默认值。方便,但也意味着当某个分支**确实**想要一个非零的进位时,你必须显式写出来。

## 验收标准

配合配套配置里的那些激励:

| 时间 | op    | a          | b          | 期望 `y`     | `carry` | `zero` |
|------|-------|------------|------------|--------------|---------|--------|
|  0   | `000` | `00001111` | `00000101` | `00010100`   | `0`     | `0`    |
| 20   | `001` | `00001111` | `00001111` | `00000000`   | `0`     | `1`    |
| 40   | `010` | `00001111` | `00001111` | `00001111`   | `0`     | `0`    |
| 60   | `101` | `10110000` | n/a        | `01100000`   | `0`     | `0`    |
| 80   | `111` | `10110000` | n/a        | `10110000`   | `0`     | `0`    |

## 再进一步

- 加一个 **signed** 标志(二补码 SUB 的负结果)。
- 加一个 **rotate** opcode——和 SHL 一样,但最高位回绕到第 0 位。
- 加一个 **multiply** opcode,在两个独立的输出端口上产出一个 16 位结果。多数小 FPGA 有专门的 DSP 块来做这个——重新综合时留意你的资源使用率。

这个 ALU 是 Expert 级 CPU 项目的一块直接积木——把这个设计保持干净——你会在那里把它接上去。

## 要点

- 一个 ALU 是操作数进、结果与标志出。opcode 选择这一块执行哪个操作。
- 你写的那个 `+` 藏着一个真实的选择:行波进位(小、慢、延迟随字长增长)对超前进位(更大、快、延迟大致恒定),用 generate/propagate 两项来做。
- **进位 ≠ 溢出。**进位是无符号的第 9 位;溢出是 `carry_in(MSB) xor carry_out(MSB)`,只对有符号值才要紧。
- 在进程顶部给每个标志一个合理的默认值,然后只在某个分支真正需要时才去覆盖——这就是你避免锁存器和漏掉情形的办法。
