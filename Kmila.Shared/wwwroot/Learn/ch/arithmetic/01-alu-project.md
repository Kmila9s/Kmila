# 项目:带标志位的 8 位 ALU

**算术逻辑单元**(ALU)是任何 CPU 的跳动心脏。给它两个操作数和一个 opcode,它返回一个结果以及一些描述刚才发生了什么的标志位(溢出了吗?结果是零吗?等等)。

## 你要构建什么

一个支持以下操作的 8 位 ALU:

| Opcode | 名称     | 公式                       |
|--------|----------|----------------------------|
| `000`  | ADD      | `y = a + b`                |
| `001`  | SUB      | `y = a - b`                |
| `010`  | AND      | `y = a and b`              |
| `011`  | OR       | `y = a or  b`              |
| `100`  | XOR      | `y = a xor b`              |
| `101`  | SHL      | `y = a 左移 1 位`          |
| `110`  | SHR      | `y = a 右移 1 位`          |
| `111`  | PASS_A   | `y = a`(直通)             |

外加两个标志位输出:

- `zero` —— 当 `y` 全是零时为高
- `carry` —— ADD/SUB 的进位输出;其它操作请驱动 `'0'`

## 脚手架给了你什么

起步代码声明了 entity、`result` 与 `cout` 信号,以及一个已经处理了 ADD 和 SUB 的 `process(op, a, b)` 框架。你的任务是补完 `case` 语句的另外六个分支。

## 提示

- **AND / OR / XOR** 各一行 —— 直接按位赋值:

  ```vhdl
  when "010" => result <= a and b;
  ```

- **SHL** 与 **SHR** 用 `'0'` 补位:

  ```vhdl
  when "101" => result <= a(6 downto 0) & '0';
  when "110" => result <= '0' & a(7 downto 1);
  ```

- **PASS_A** 直接把 `a` 复制给 `result`。

记得对逻辑操作要驱动 `cout <= '0'` —— 你已经在 process 顶部做了一次,所以任何不覆盖它的分支都会继承这个默认值。挺好,但也意味着,如果某个分支**确实**需要非零进位,你必须显式指定。

## 验收标准

配合配套配置的激励:

| 时间 | op    | a          | b          | 期望 `y`     | `carry` | `zero` |
|------|-------|------------|------------|--------------|---------|--------|
|  0   | `000` | `00001111` | `00000101` | `00010100`   | `0`     | `0`    |
| 20   | `001` | `00001111` | `00001111` | `00000000`   | `0`     | `1`    |
| 40   | `010` | `00001111` | `00001111` | `00001111`   | `0`     | `0`    |
| 60   | `101` | `10110000` | n/a        | `01100000`   | `0`     | `0`    |
| 80   | `111` | `10110000` | n/a        | `10110000`   | `0`     | `0`    |

## 再进一步

- 加一个 **signed** 标志(二补码 SUB 的负结果)。
- 加一个 **rotate** opcode —— 和 SHL 一样,但最高位回到第 0 位。
- 加一个 **multiply** opcode,把 16 位结果放到两个独立的输出端口上。多数小 FPGA 内置 DSP 块来做乘法 —— 重新综合时注意使用率。

这个 ALU 是 Expert 级 CPU 项目的直接积木 —— 把这个设计保持干净,你将在那里接上去。
