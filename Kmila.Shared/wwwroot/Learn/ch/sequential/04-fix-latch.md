# 修一修：意外的锁存器

这是几乎每个 VHDL 学生至少会犯一次的两三个 bug 之一。代码看着没问题，构建通过，仿真输出貌似合理 —— 当你综合时，工具却警告说它推断出了一个你没要求的**锁存器**（latch）。

## 起始代码

```vhdl
architecture rtl of latch_bug is
begin
  process(enable, a, b)
  begin
    if enable = '1' then
      y <= a and b;
    end if;
    -- 缺失：当 enable = '0' 时 y 应该是什么？
  end process;
end architecture rtl;
```

## 出了什么问题

在一个纯组合进程里，每个输出必须在经过进程的**每条路径上**都被赋值。这段代码只在 `enable = '1'` 时赋 `y`。当 `enable = '0'` 时，进程对 `y` 只字未提。

VHDL 对"你没告诉我这个信号怎么办"的解决办法是：**记住上一个值**。那就是锁存器 —— 一种透明的存储元素。综合会推断出它，你的设计就会出现时序路径的噩梦，板子在信号跳变时会产生毛刺。

## 你的任务

打开示例，让设计变成**纯组合** —— 没有锁存器、没有触发器，只有门。两种惯用修法：

**修法 1：顶部的默认赋值**

```vhdl
process(enable, a, b)
begin
  y <= '0';                       -- 默认值
  if enable = '1' then
    y <= a and b;
  end if;
end process;
```

一个信号在进程内可以被多次赋值 —— 只有最后一次生效。顶部的默认值意思是"除非有东西覆盖我，我就是 `'0'`"。

**修法 2：补全 `if`**

```vhdl
process(enable, a, b)
begin
  if enable = '1' then
    y <= a and b;
  else
    y <= '0';
  end if;
end process;
```

两者都对。两者生成相同的硬件。挑更适合你所做设计的那一种。

## 验证修法

修完后运行仿真。在波形里：

- 在 `15–25 µs`（`enable = '1'` 且 `a=b='1'`）：`y = '1'`。
- 在其余时刻：`y = '0'`。

修复前，当 `enable` 回落为 `'0'` 时 `y` 会保持为 `'1'` —— 那就是锁存器在保持上一个值，正是你要避免的。

## 规则

在一个组合进程里，**每个输出都必须在每一条路径上被赋值**。如果你做不到这一点，要么加默认值，要么你实际上想要一个触发器 —— 那就应当改用时钟进程，并对这个决定负责。
