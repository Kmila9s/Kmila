# δ 周期与竞争条件

仿真器需要为"同一时刻发生的两件事"给出一个确定性的顺序。VHDL 的答案是 **δ 周期**（delta cycle）：一段无限短的时间切片，用来分隔因与果。

## 什么是 δ 周期

仿真时间以实际步长（按 ns、µs、ms 计量）推进。但在单个时间步之内，变化可以按 **δ 周期**顺序发生：

- δ₀：你调度了一次信号更新。
- δ₁：更新生效；任何对该信号敏感的进程现在看到新的输入。
- δ₂：这些进程调度各自的更新。
- δ₃：这些更新生效。
- ……

每个 δ 都是"零真实时间"，但仍然代表一个因果步骤。仿真器会不断循环 δ 周期，直到没有任何东西需要再更新 —— 到那时，并且只有到那时，真实时间才会向前推进。

## 为什么需要它

考虑两个信号在同一个时钟边沿上更新：

```vhdl
process(clk)
begin
  if rising_edge(clk) then
    a <= x;
    b <= y;
  end if;
end process;
```

没有 δ 周期的话，仿真器只能任意挑一个顺序 —— `a` 是在 `b` 之前更新？还是之后？还是同一瞬间？δ 周期回避了这个问题：两个赋值都在 δ₀ 调度、都在 δ₁ 生效。任何读取 `a` 或 `b` 的进程会同时看到两个新值。

## 竞争条件的陷阱

看这段：

```vhdl
process(a)
begin
  b <= a;
end process;

process(b)
begin
  c <= b;
end process;
```

当 `a` 变化时，第一个进程触发并调度 `b`。在 δ₁ 时刻，`b` 有了新值。第二个进程随之触发，调度 `c`。在 δ₂ 时刻，`c` 拿到正确的值。

但如果你把两个进程的位置调换，结果会变吗？**不会。** δ 周期保证两条路径产生相同的最终结果 —— 尽管文件中进程的"顺序"不同。这正是 δ 周期存在的意义。

## 在哪儿会出错

问题出在当你把**信号**语义与"在同一个 tick 内，我需要这个先于那个发生"的需求混在一起时。例如：

```vhdl
process(clk)
begin
  if rising_edge(clk) then
    a <= b + 1;     -- a 在 tick 末更新
    b <= a + 1;     -- b 读到的是旧的 a
  end if;
end process;
```

如果你假设"第 1 行先执行，所以第 2 行运行时 `a` 已经更新"，那就错了。`a` 在 tick 末才更新，`b` 读到的是 `a` 的旧值。结果：两者都基于旧数据递增，而不是基于对方的新数据。

把信号换成 variable，就获得 C 风格的语义：

```vhdl
process(clk)
  variable aa, bb : integer;
begin
  if rising_edge(clk) then
    aa := bb + 1;   -- 立即生效
    bb := aa + 1;   -- 看到新的 aa
  end if;
end process;
```

现在它就按软件程序员期望的方式工作了。

## 关键要点

- δ 周期是仿真器让并发逻辑具有确定性的方式。
- 信号赋值在 δ 周期**之后**才生效。变量则不然。
- 如果你的测试台在时钟边沿附近表现"诡异"，先怀疑 δ 周期的定序问题，再去怪工具。
