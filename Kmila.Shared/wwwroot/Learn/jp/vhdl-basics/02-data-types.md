# データ型:`std_logic`、ベクトル、`unsigned`、`integer`

VHDL は **強く型付けされた** 言語だ。ポートが `in std_logic` と宣言されているのを見たら、コンパイラは明示的な変換なしにそれを別の型のものへ配線させてくれない。各信号に正しい型を選ぶことは、きれいな VHDL を書く仕事の半分を占める。

## `std_logic` — 万能の線

**9 値** の IEEE 1164 ロジックの 1 ビットだ。そう、9 つある。

| 値 | 意味 |
|-------|---------|
| `'0'` | 強駆動の Low |
| `'1'` | 強駆動の High |
| `'Z'` | ハイインピーダンス(トライステートオフ) |
| `'L'` | 弱い Low(プルダウン) |
| `'H'` | 弱い High(プルアップ) |
| `'X'` | 強い不定 — たとえば 2 つのドライバが異なる値で競合している状態 |
| `'U'` | 未初期化 — 信号が一度も代入されていない |
| `'W'` | 弱い不定 |
| `'-'` | don't care(`std_match` のパターン / 合成ヒントとして使う) |

なぜ 2 つではなく 9 つなのだろうか。現実の線は単なる「0 か 1」ではないからだ。浮いている(`'Z'`)こともあれば、弱く引っ張られている(`'L'` / `'H'`)ことも、本当に競合している(`'X'`)こともある。これこそが `std_logic` を **解決可能(resolved)** な型にしている理由だ。複数のドライバが 1 本の線を共有するとき、解決関数が結果を決定する。強い値は弱い値に勝ち、食い違う 2 つの強い値は `'X'` を生み、どのドライバも駆動していない線は `'Z'` に落ち着く。

合成ではハードウェアに届くのは `'0'`、`'1'`、`'Z'` だけだ。残りはシミュレーション上の診断情報だ。波形に `'U'` が見えたら、書き込まれる前に読まれている信号があるということだ。`'X'` の縞模様はたいてい、2 つのアクティブなドライバを持つバスを意味する。

> 解決されない従兄弟分として `std_ulogic` もある(`u` は "unresolved" の意味だ)。`std_logic` は文字どおり `std_ulogic` に解決関数を加えたものだ。既定では `std_logic` を使おう — バスにはその解決の挙動こそが欲しいものだからだ。

## `std_logic_vector` — バス

`std_logic` の固定幅配列だ。

```vhdl
signal data : std_logic_vector(7 downto 0);  -- 8 ビット、インデックス 7..0
signal addr : std_logic_vector(0 to 15);     -- 16 ビット、インデックス 0..15
```

`downto` は圧倒的によく使われる方向だ。数値の書き方(MSB が左)と一致するので、`data(7)` が最上位ビットになる。プロジェクトごとに 1 つの方向を選び、それを貫こう。`to` と `downto` を混ぜると、バスが気付かないうちに反転するという古典的なトラブルの元になる。

リテラル:

```vhdl
data <= "10101010";      -- 2 進リテラル、1 文字が 1 ビット
addr <= x"CAFE";         -- 16 進リテラル(幅は 4 ビットの倍数であること)
data <= (others => '0'); -- アグリゲート:全ゼロ、どんな幅でも対応
data <= (0 => '1', others => '0'); -- ビット 0(LSB)だけ High
```

`(others => '0')` の形は愛すべきものだ。後で幅を変えても自動的に追従するので、古くなることがない。

## `unsigned` / `signed` — 算術ができるベクトル

`std_logic_vector` は「ただのビットの袋」だ。数値的な意味を持たないので、`numeric_std` のもとでは `slv1 + slv2` はコンパイルエラーになる。加算や減算をするには `unsigned` か `signed` が必要だ。

```vhdl
use IEEE.NUMERIC_STD.ALL;

signal a, b, sum : unsigned(7 downto 0);
...
sum <= a + b;   -- 動く:同じ幅の unsigned 同士の加算
```

この 2 つの型が違うのは、最上位ビットの読み方だけだ。`unsigned` はすべてのビットを大きさとして扱い、`signed` は MSB を 2 の補数の符号として扱う。

両者の間の行き来 — これらは、あなたが絶えず使うことになる 4 つの変換だ。

```vhdl
-- 同じビットを unsigned として再解釈する(算術用)
u   <= unsigned(slv);

-- unsigned をただのビットとして再解釈する(外の世界 / ポート向け)
slv <= std_logic_vector(u);

-- unsigned -> integer、インデックスや定数のため
idx <= to_integer(u);

-- integer -> unsigned;幅を必ず指定すること
u   <= to_unsigned(42, 8);
```

`unsigned(slv)` と `std_logic_vector(u)` は **型キャスト** だ。ビットに貼られたラベルを変えるだけで、ビット自体は変えない。`to_integer` と `to_unsigned` は、実際に計算を行う **関数** だ。初心者によくある誤りは、ベクトルに対して `to_unsigned` を呼ぶ(これは integer を取る)ことや、integer を `unsigned(…)` でキャストする(キャストは配列型どうしの間でしか効かない)ことだ。

もう一つ、オーバーフローのバグを防いでくれるのが `resize` だ。これは新しい幅に合わせてパディングまたは切り詰めを行う。`unsigned` は **ゼロ拡張**、`signed` は **符号拡張** するので、算術の前に値を保つ。

```vhdl
wide <= resize(a, 9) + resize(b, 9);  -- 9 ビットの結果でキャリーを保持する
```

経験則:**ポート** には `std_logic_vector` を使い(対象が最も広いので)、実際に算術を行う architecture の内部で `unsigned` / `signed` に変換しよう。

## `integer` — インデックスと計数のために

ループカウンタ、定数、そしてポート境界を越えないものには `integer`(または制約付きサブタイプ)を使う。

```vhdl
constant DEPTH : integer := 32;
for i in 0 to DEPTH - 1 loop ...
```

無制約の `integer` は、シミュレーションでは少なくとも 32 ビットだ(範囲は −2³¹+1 から 2³¹−1)。ハードウェアでは、シンセサイザがレジスタのサイズを決められるよう、ほとんどの場合は制約付きの範囲が欲しくなる。

```vhdl
signal counter : integer range 0 to 255;  -- ちょうど 8 ビットに合成される
```

無制約の `integer` カウンタは、欲しくもない 32 個のフリップフロップを消費してしまう。

## 列挙型 — FSM の状態のために

ステートマシンには、読みやすい型を宣言しよう。

```vhdl
type state_t is (S_IDLE, S_START, S_ACTIVE, S_DONE);
signal state : state_t;
```

こうすると `state <= "010"` の代わりに `state <= S_ACTIVE` と書ける。バイナリ(あるいは one-hot)エンコーディングはシンセサイザが選んでくれるし、こだわりがあれば属性でヒントを与えられる。コードは仕様書のように読め、波形には生のビットではなく状態の *名前* が表示される。

## 覚えておくべきこと

- 単線 → `std_logic`。バス → `std_logic_vector`。どちらも `STD_LOGIC_1164` から来る。
- 算術が必要?そのときは `unsigned`(または `signed`)と `IEEE.NUMERIC_STD` を使おう。`std_logic_vector` には数値的な意味がない。
- `unsigned(x)` / `std_logic_vector(x)` はキャスト(ビットのラベルを変える)、`to_integer` / `to_unsigned` は関数(そして `to_unsigned` には幅が必要)だ。
- **ポート** を `std_logic_vector` で宣言すると、entity の移植性が最大になる。変換は内部で行おう。
- `integer` の範囲は制約し、FSM の状態には列挙型を使おう。
