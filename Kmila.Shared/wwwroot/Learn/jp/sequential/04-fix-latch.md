# 修正せよ: 偶発的ラッチ

これはすべての VHDL 学生が少なくとも一度は書くバグの 1 つです。紙の上では正しく見え、エラーなしでビルドされ、もっともらしい出力でシミュレーションします — そして合成するとツールは、あなたが頼んでいない **ラッチ** を推論したと警告します。

## スターター

```vhdl
architecture rtl of latch_bug is
begin
  process(enable, a, b)
  begin
    if enable = '1' then
      y <= a and b;
    end if;
    -- Missing: what should y be when enable = '0'?
  end process;
end architecture rtl;
```

## 何が悪いか

純粋な組合せプロセスでは、すべての出力はプロセスを通るすべての経路で代入されなければなりません。これは `enable = '1'` のときだけ `y` を代入しています。`enable = '0'` のとき、プロセスは `y` について何も言いません。

VHDL の「この信号をどうすべきか言わなかった」への解決策: **前の値を覚えておく**。それがラッチ — 透明なメモリ要素です。合成はこれを推論し、設計はタイミングパスの悪夢を抱え、ボードは信号遷移でグリッチします。

## ミッション

サンプルを開き、設計を **純粋に組合せ** にする — ラッチなし、フリップフロップなし、ただのゲート。2 つの慣用的な修正:

**修正 1: 上部にデフォルト代入**

```vhdl
process(enable, a, b)
begin
  y <= '0';                       -- default
  if enable = '1' then
    y <= a and b;
  end if;
end process;
```

信号はプロセス内で複数回代入できます — 最後の代入だけが有効になります。上部のデフォルトは「何かが上書きしない限り、`'0'` であれ」を意味します。

**修正 2: `if` を完成させる**

```vhdl
process(enable, a, b)
begin
  if enable = '1' then
    y <= a and b;
  else
    y <= '0';
  end if;
end process;
```

両方とも正しいです。両方とも同じハードウェアを生成します。作業中の設計に読みやすい方を選んでください。

## 修正を検証する

修正後、シミュレーションを実行します。波形で:

- `15–25 µs` の間(`enable = '1'` かつ `a=b='1'` のとき): `y = '1'`。
- その他のすべての時間: `y = '0'`。

修正前は、`enable` が `'0'` に戻っても `y` は `'1'` に留まりました — それがラッチが前の値を保持していることで、まさに避けたいものです。

## ルール

組合せプロセスでは、**すべての出力はすべての経路で代入されなければなりません**。それを満たせない場合、デフォルトを追加するか、あるいは実際にはフリップフロップが欲しいのです — その場合はクロック同期プロセスに移り、その決定を自分のものにしましょう。
