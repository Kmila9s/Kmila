# 修正:意図せず推論されたラッチ

これは VHDL のあらゆる学生が少なくとも 1 度は書く 2、3 のバグの 1 つ。コードは紙の上では正しく見え、エラーなくビルドされ、それらしい出力でシミュレーションが通る — それから合成すると、ツールが頼んでもいない**ラッチ**を推論したと警告する。

## スタータ

```vhdl
architecture rtl of latch_bug is
begin
  process(enable, a, b)
  begin
    if enable = '1' then
      y <= a and b;
    end if;
    -- 抜け:enable = '0' のとき y はどうあるべきか?
  end process;
end architecture rtl;
```

## どこがダメか

純粋に組合せの process では、すべての出力が process を通る**すべての経路**で代入されなければならない。これは `enable = '1'` のときだけ `y` を代入する。`enable = '0'` のとき、process は `y` について何も言わない。

「この信号にどうしろと言われていない」に対する VHDL の答え:**前の値を覚えておく**。それがラッチ — 透明な記憶要素。合成はそれを推論し、設計はタイミングパスの悪夢を抱え、ボードは信号遷移でグリッチする。

## あなたのミッション

サンプルを開いて設計を**純粋に組合せ**にする — ラッチなし、フリップフロップなし、ただのゲート。慣用句的な修正は 2 つ:

**修正 1:先頭にデフォルト代入**

```vhdl
process(enable, a, b)
begin
  y <= '0';                       -- デフォルト
  if enable = '1' then
    y <= a and b;
  end if;
end process;
```

信号は process 内で複数回代入できる — 最後のものだけ有効。先頭のデフォルトは「何かが上書きしない限り、私は `'0'`」を意味する。

**修正 2:`if` を完成させる**

```vhdl
process(enable, a, b)
begin
  if enable = '1' then
    y <= a and b;
  else
    y <= '0';
  end if;
end process;
```

両方正しい。両方とも同一のハードウェアを生成する。設計に応じて読みやすい方を選ぶ。

## 修正を検証

修正後にシミュレーションを実行。波形で:

- `15–25 µs`(`enable = '1'` かつ `a=b='1'`):`y = '1'`。
- それ以外の時間:`y = '0'`。

修正前は `enable` が `'0'` に落ちても `y` は `'1'` のままだった — それがラッチが前の値を保持している状態で、まさにあなたが避けようとしているもの。

## ルール

組合せ process では、**すべての出力がすべての経路で代入されなければならない**。それを満たせないなら、デフォルトを追加するか、本当はフリップフロップが欲しい — その場合はクロック付き process に移行し、その決定を自分のものにする。
