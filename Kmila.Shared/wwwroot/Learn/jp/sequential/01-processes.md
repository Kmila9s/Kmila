# プロセスとセンシティビティリスト

VHDL のプロセス外のすべては並行です — ワイヤとゲート。あるクロックサイクルから次へと何かを **記憶** したい瞬間、プロセスが必要になります。

## プロセスとは何か

`process` は VHDL アーキテクチャ内の逐次コードのブロックです。その行はソフトウェアと同じように上から下へと読まれます。しかしプロセス自体は、**センシティビティリスト** 内の何かが変化したときだけ「実行」されます。

```vhdl
process(clk, reset)
begin
  if reset = '1' then
    q <= '0';
  elsif rising_edge(clk) then
    q <= d;
  end if;
end process;
```

このブロックは以下を意味します: 「`clk` または `reset` が変化するたびに、私の本体を再評価する」。

## 99% の場面で見る 2 つの形

### 組合せプロセス

センシティビティリスト = 内部で読むすべての入力。クロックなし。出力は入力の純粋関数。

```vhdl
process(a, b, sel)
begin
  if sel = '0' then
    y <= a;
  else
    y <= b;
  end if;
end process;
```

2-to-1 マルチプレクサに合成されます。ストレージなし。

### クロック同期 (順序) プロセス

センシティビティリスト = `(clk, reset)`。代入は `rising_edge(clk)` (または運が悪いと `falling_edge`) の内部でのみ発生します。出力は **レジスタ付き** — クロックエッジでのみ変化します。

```vhdl
process(clk, reset)
begin
  if reset = '1' then
    q <= (others => '0');
  elsif rising_edge(clk) then
    q <= d;
  end if;
end process;
```

これが古典的な D フリップフロップパターンです。

## センシティビティリストの罠

本体が読む信号をリストし忘れると、シミュレーションと合成は一致しません:

- **シミュレーション**: その信号が変化してもプロセスは再評価されません。波形が間違って見えます。
- **合成**: ツールは本体を読み、すべての読み出しを認識し、とにかく正しいハードウェアを構築します。

結果: テストベンチはパスするがボードは動かない — あるいはその逆。現代の VHDL-2008 では、これを完全に避けるために `process(all)` と書けます:

```vhdl
process(all)  -- include every signal read in the body
begin
  ...
end process;
```

Kmila のパーサは `process(all)` を受け入れ、新設計ではほとんどのチームがこれを使います。

## 経験則

- センシティビティ = `(clk, reset)` のみ → **レジスタ** (フリップフロップ) を記述している。
- センシティビティ = 読むすべての入力 → **組合せロジック** を記述している。
- センシティビティにクロック同期と非同期の信号が混ざっている → ほぼ確実にバグ。

## 覚えておくべきこと

- プロセスは、そうでなければ並行なファイル内の逐次コードの単位。
- クロック同期プロセス (`rising_edge(clk)`) はフリップフロップに合成される。これがメモリを得る方法。
- 読むすべての信号をリストするか、`process(all)` を使ってツールに任せる。
