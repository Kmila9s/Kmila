# プロジェクト:UART 送信器

UART(Universal Asynchronous Receiver / Transmitter、汎用非同期送受信器)は、ほとんどの組込み設計者が最初に作る本物のプロトコルだ。ポイントツーポイントで、全二重で、必要な配線はたった 3 本(TX、RX、GND)だ。あらゆる FTDI の USB シリアル変換器、あらゆる Arduino の `Serial.print`、あらゆる古いターミナル — その底はどれも UART だ。

このプロジェクトは **送信** 側を作る。受信側は、これを終えたあとの素晴らしい次のプロジェクトだ。

## 非同期:クロック線がない

UART の「A」こそが挑戦のすべてだ。SPI や I2C と違って、両端は **クロック線を共有しない**。受信側は、タイミングをデータそのものから復元しなければならない。それがうまくいくのは、両端が前もって **ボーレート**(1 秒あたりのビット数)と **フレーム形式** で合意している場合だけだ。どちらかを間違えると、ゴミを受信する — ボーレート不一致の古典的な症状だ。

ESCOM のコースでは、これは RS-232 規格の下に位置する。人がよく混同する 2 つのものを分けておく価値がある:**UART** はバイトを直列化するデジタル論理(ここで作るもので、0 V / 3.3 V の論理レベル)であり、一方 **RS-232** はそれらのレベルを、ケーブルを駆動するために *反転した* 極性でおよそ ±12 V に変換する電気規格だ。MAX232 のようなラインドライバが、あなたの UART ピンと本物の DB-9 コネクタの間に座る。あなたの VHDL が扱うのは、常にきれいな論理レベル側だけだ。

## フレーム形式(パリティなし、8 ビットデータ、ストップ 1)

```
  Idle  Start   Bit0  Bit1  Bit2  Bit3  Bit4  Bit5  Bit6  Bit7   Stop   Idle
  ────┐      ┌───── ... ─────────────────────────────── ... ─────┐──────
      │      │
      └──────┘
    線は通常 High ('1');スタートビットは立ち下がりエッジ。
```

これが「8N1」だ:**8** データビット、パリティ **N**one(なし)、**1** ストップビット — ワイヤ上ではバイトあたり 10 ビットだ。重要なルール:

- **Idle** は High。壊れた線や切れた線は、ゼロの連続ではなく idle として読まれる。
- **Start** ビットは Low。その立ち下がりエッジが、受信側が得る唯一のタイミング基準。
- **Data** は **LSB から先** に出る — ビット 7 より前にビット 0。
- **Stop** ビットは High で、これが次のフレームに新鮮な立ち下がりエッジが使えることも保証する。

各ビットは `tx` 上でちょうど `clk_freq / baud` クロックサイクルだけ保持される。50 MHz クロックで 115,200 ボーなら、50,000,000 / 115,200 ≈ 434 サイクル/ビットだ。

## あなたの仕事

1. 約 434 サイクルごとに 1 サイクル幅の `baud_tick` を出すクロックカウンタを作る。
2. `send = '1'` で `data` を 10 ビットシフトレジスタにラッチする:`{ stop_bit, data[7..0], start_bit } = 1 & data & 0`。`busy <= '1'` を駆動する。
3. 各 `baud_tick` でレジスタを右シフトする(スタートビットが先に出て、次にデータの LSB から MSB、最後にストップビット)。
4. 10 番目の tick の後、`busy` を下げ、`tx` を idle High にする。

## 雛形

entity と idle 状態は提供済みだ。`tx` はデフォルト High、`busy` はデフォルト Low だ。それらのデフォルトの間のすべてが、あなたの責任だ。

```vhdl
architecture rtl of uart_tx is
  signal tx_reg : std_logic := '1';
begin
  tx   <= tx_reg;
  busy <= '0';       -- TODO
end architecture rtl;
```

## 推奨する構造

カウンタ 2 つ + シフトレジスタ 1 つ:

```vhdl
signal clk_count  : unsigned(9 downto 0);   -- 0..434
signal bit_count  : unsigned(3 downto 0);   -- 0..9
signal shift_reg  : std_logic_vector(9 downto 0);
signal sending    : std_logic := '0';
```

- `send = '1'` かつ `sending = '0'` のとき:
  - `shift_reg <= '1' & data & '0';` をロードする
  - `sending <= '1';  clk_count <= 0;  bit_count <= 0;`
- `sending = '1'` の間:
  - `clk_count <= clk_count + 1;`
  - `clk_count = BAUD_PERIOD - 1` のとき:
    - `tx_reg <= shift_reg(0);`
    - `shift_reg <= '1' & shift_reg(9 downto 1);` — 右シフトし、上位を idle で詰める
    - `bit_count <= bit_count + 1;`
    - `clk_count <= 0;`
  - `bit_count = 10` のとき:
    - `sending <= '0';`

`BAUD_PERIOD` を generic にしておけば、シミュレーション用に小さくでき(例:5 サイクル/ビット)、同じ論理がハードウェアではフルスピードで動く。

## どれだけのタイミング誤差を許せるか

共有クロックがないので、受信側は各ビットの中央付近でサンプリングし、フレームにわたって少しずつドリフトする。10 ビット周期にわたって、累積誤差は半ビット未満に留まらなければならないので、各端のボー誤差はおよそ ±2〜3% 未満に収める必要がある。整数分周器はぴったり当たることがめったにない:50 MHz で 434 サイクル/ビットだと 115,207 ボーになり — 誤差 0.006%、まったく安全だ。扱いにくいクロックだと悪く丸まることがあり、それが多くの実 UART が小数分周器を加える理由だ。受信側は、ボーレートの 16 倍で **オーバーサンプリング** することで余裕を稼ぐ:スタートエッジを見つけ、それからカウント 8(ビット中央)で、そして以後 16 ティックごとにサンプリングする。

## テストすべきこと

`data = "01001000"`(ASCII の `'H'`)で `send = '1'` を駆動する。フレーム完了後、`tx` 波形にはちょうど 10 ビット周期の活動が現れるはずだ:

1. スタート(Low)
2. データのビット 0(つまり LSB:`0`)
3. `0`
4. `0`
5. `1`
6. `0`
7. `0`
8. `1`
9. `0`(MSB)
10. ストップ(High)

それから idle High に戻る。Waveforms タブで拡大し、パターンを 1 ビットずつ確認しよう。

## よくある落とし穴

- **ビット順の間違い。** MSB を先に送るのは、断トツで最もよくあるバグだ。雛形の `'1' & data & '0'` と右シフトで、LSB 先がタダで手に入る — それを「直そう」としないこと。
- **ビット数のオフバイワン。** 8N1 は *10* ティックであって 8 ではない。スタートやストップのビットを忘れるとフレームが切れる。
- **フレームの途中での再トリガ。** `send` は `sending = '0'` のときだけ尊重しよう。さもないと 2 回目の要求が、飛行中のフレームを壊す。そのための `busy` だ。
- **ボーレート不一致。** 受信側がバイト数は正しいのに値が化けていたら、論理より先に分周器を疑おう。

## さらに進めるなら

- **FIFO** を追加して、複数バイトをキューできるようにする。`send` は「push」になる。
- **RX** 側を作る:16 倍でオーバーサンプリングし、スタートエッジを見つけ、ビット中央でサンプリングする。
- フレームをパラメータ化する:パリティ、7 ビット対 8 ビットデータ、ストップビット 1 対 2。

## 覚えておくべきこと

- UART は **非同期** だ:クロック線がないので、両端が前もってボーレートとフレーム形式で合意していなければならない。
- 8N1 はワイヤ上で **10 ビット** だ — idle は High、スタートは Low、8 データビットは **LSB から先**、ストップは High。
- 1 ビットは `clk_freq / baud` サイクル続く。1 サイクルの `baud_tick` がシフトレジスタのペースを刻む。
- 各端のボー誤差を約 2% 未満に保とう。RX 側は **オーバーサンプリングしてビット中央でサンプリングする** ことで余裕を買う。
- **UART** は論理、**RS-232** は、その上にラインドライバが加える ±12 V の電気層だ。
