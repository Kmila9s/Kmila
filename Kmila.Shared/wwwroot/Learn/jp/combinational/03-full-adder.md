# サンプル:4 ビットリップルキャリー加算器

2 つの 2 進数を足すことは、デジタル算術の「hello world」だ。このサンプルは、キャリー入力とキャリー出力を備えた 4 ビット加算器を作る — より大きな ALU の中や、CPU のアドレスインクリメント論理の中にタイル状に敷き詰めるのと、まさに同じセルだ。これが組合せの単元で最初の回路(「加算器 / 減算器回路(circuito sumador/restador)」)なのには理由がある。いったん足し算ができれば、減算、比較、計数のすべてが後に続くからだ。

## 1 ビットから始める:全加算器

4 ビット版の前に、それを構成する 1 ビットの **全加算器(full adder)** を知ろう。ビット `i`、キャリー入力 `cin` について:

```
sum  = a xor b xor cin
cout = (a and b) or (cin and (a xor b))
```

和は 3 つの入力すべての XOR(奇パリティ)で、キャリーは「3 つの入力のうち 2 つ以上が 1」だ。これを 4 つ連ね — それぞれの `cout` を次の `cin` に供給して — **リップルキャリー(ripple-carry)** 加算器ができる。名前は文字どおりで、最上位の和ビットが確定する前に、キャリーが LSB から MSB まで波及(ripple)しなければならない。だからこの構造はシンプルだが、最速ではないのだ。

## インタフェース

```vhdl
port (
  a    : in  std_logic_vector(3 downto 0);
  b    : in  std_logic_vector(3 downto 0);
  cin  : in  std_logic;
  sum  : out std_logic_vector(3 downto 0);
  cout : out std_logic
);
```

## 本体

4 つの全加算器を手で配線する代わりに、`numeric_std` に算術をやらせて、キャリーだけを取り出す。

```vhdl
signal t : unsigned(4 downto 0);
...
t    <= resize(unsigned(a), 5) + resize(unsigned(b), 5) + ("0000" & cin);
sum  <= std_logic_vector(t(3 downto 0));
cout <= t(4);
```

何が起きているか:

- `unsigned(a)` と `unsigned(b)` は、`+` 演算子のためにベクトルを数値型として再解釈する。
- `resize(…, 5)` は 5 ビットへゼロ拡張し、和が最上位ビットへオーバーフローする余地を作る。
- `("0000" & cin)` は LSB に `cin` だけを持つ 5 ビットの値を作り、きれいに足し込めるようにする。
- 加算の後、`t(3 downto 0)` が和で、`t(4)` がキャリー出力だ。

> 2 つのスタイル — 明示的な 4 つの全加算器と、リサイズした `unsigned` への 1 つの `+` — は *同じ* リップルキャリーハードウェアに合成される(現代のツールはより速いキャリー構造に格上げすることさえある)。`+` 版が実際に書くもので、ゲートレベル版は *説明できる* べきものだ。

## なぜ 5 ビットなのか

2 つの 4 ビット数にキャリー入力を足すと、`1111 + 1111 + 1 = 11111` — 5 ビット — という大きさの結果になり得る。4 ビットの入れ物で計算すると、最上位ビットが黙って失われる。1 ビット余分にリサイズするのが安全なイディオムで、ビット 4 が *まさに* キャリー出力だ。

## 減算器を作る

コースは加算器と減算器を組にしており、2 の補数ではこれらはほぼ同じ回路だ。`a − b` を計算するには、`b` のビットごとの補数を足し、キャリー入力を 1 に強制する。

```vhdl
t <= resize(unsigned(a), 5) + resize(unsigned(not b), 5) + "00001";
```

これは `a + (¬b) + 1 = a − b` だ。実際の加算器 / 減算器は、ビットごとに 1 つの XOR(`add_sub` 線で制御)を足し、その同じ線を `cin` に供給する — 1 ビットの制御で、ユニット全体が 2 つの演算の間で切り替わる。

## このサンプルがすること

シミュレーション設定は `a` と `b` をいくつかのパターンに通す(`3+5 = 8`、次にキャリーを生む `10 + 6 = 16`、そして `10 + 15 = 25`…)。波形は `sum` と `cout` が **組合せ的に** 変化する様子を見せる — この設計にはレジスタがないので、クロックは要らない。

## あなたの番

- **パラメトリックにしてみよう。** entity に `generic (N : integer := 4)` を追加し、`4` が出てくるすべての場所で `N` を使う。これで、任意の幅でインスタンス化できる `adder_N` ができる。
- 上の **加算器 / 減算器** を `add_sub` 制御入力付きで作ってみよう。
- **2 つを配線してつなごう。** 1 つは下位ニブル、もう 1 つは上位ニブル用で、最初の `cout` を 2 つ目の `cin` に供給すれば、8 ビットのリップルキャリー加算器ができる — そして、なぜキャリー遅延が幅とともに増えるのかが体感できる。

## 覚えておくべきこと

- 全加算器は `sum = a xor b xor cin`、`cout = majority(a, b, cin)` だ。これを連ねて幅広の数を足す。
- 算術には常に 1 ビット余分に(`resize`)与え、キャリーが失われないようにしよう。
- 減算は 2 の補数の加算だ:`a − b = a + not b + 1`。
- リップルキャリーはシンプルだが、その遅延はビット数とともに増える。
