# 並行代入:`when/else` と `with/select`

VHDL の組合せ論理は並行文で書く — process の外の各行は永続的に配線されたハードウェアの一部を記述する。同じ仕事に対して 2 つの構文フレーバが存在する:**条件**代入と**選択**代入。

## `when/else` — 条件

優先順位付きの条件のリストがあるとき、または各分岐が違う信号を調べるときに良い:

```vhdl
y <= '0' when reset = '1' else
     a   when mode  = "read" else
     b   when mode  = "write" else
     'Z';
```

最初にマッチした条件が勝つ。順序が重要 — **優先順位 MUX** にコンパイルされる:一番上の条件が `y` への最短経路を持つ。

## `with/select` — 選択

単一の式で分岐するとき(ソフトウェアの `switch` と同じ感覚)に良い:

```vhdl
with mode select
  y <=
    a   when "00",
    b   when "01",
    c   when "10",
    'Z' when others;
```

すべてのケースが同じ信号(`mode`)と比較し、`when others` がすべての可能なパターンをカバーするために必須。このスタイルは**バランスのとれた MUX** にコンパイルされる — どの分岐も特権を持たない。

## どちらを選ぶか?

- **同じ信号、多くのパターン:** `with/select` は真理値表のように読める。これを使う。
- **異なる信号、優先順位ロジック:** `when/else`。自然に合う。
- **合成結果:** どちらも現代の FPGA ではほぼ同じゲートを生む — ソースレベルでより明確な形を選ぶのがほぼ常に正解。

## 小さな罠

両形式とも、`y` が**すべての**シナリオで代入されることを要求する。`when/else` の最後の `else` を忘れたり、`with/select` の `when others` を省くとコンパイラが警告する — そしてシンセサイザは最後の値を「覚える」ためにラッチを推論する可能性がある。それはほぼ望むものではない。これは順序モジュールの fix-it 演習で再び見るラッチの罠と同じ。

## 次にどこで出てくるか

このレッスンの直後の 3-8 デコーダサンプルで `with/select` を使い、後の信号機 FSM では `when/else` をあちこちで使う。どちらも VHDL の日常食。
