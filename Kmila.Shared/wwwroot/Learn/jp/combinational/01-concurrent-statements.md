# 並行代入: `when/else` と `with/select`

VHDL の組合せ論理は並行文で記述します — プロセスの外にある各行は、恒久的に配線されたハードウェア片を記述します。同じ仕事に対して 2 つの構文フレーバが存在します: **条件付き** 代入と **選択付き** 代入です。

## `when/else` — 条件付き

条件の優先順位付きリストがあるとき、または各分岐が異なる信号をチェックするときに適しています:

```vhdl
y <= '0' when reset = '1' else
     a   when mode  = "read" else
     b   when mode  = "write" else
     'Z';
```

最初にマッチした条件が勝ちます。順序は重要 — **優先度マルチプレクサ** にコンパイルされます: 最上位の条件が `y` への最も直接的な経路を持ちます。

## `with/select` — 選択付き

単一の式で切り替えるときに適しています(ソフトウェアの `switch` 文と同じ方法):

```vhdl
with mode select
  y <=
    a   when "00",
    b   when "01",
    c   when "10",
    'Z' when others;
```

すべてのケースが同じ信号 (`mode`) と比較され、`when others` はすべての可能なパターンをカバーするために必須です。このスタイルは **バランス型マルチプレクサ** にコンパイルされます — どの分岐も特別扱いされません。

## どちらを選ぶべきか?

- **同じ信号、多くのパターン:** `with/select` は真理値表のように読める。これを使う。
- **異なる信号、優先度ロジック:** `when/else`。自然な相性。
- **合成結果:** どちらも現代の FPGA ではほぼ同じゲートを生成する — ソースレベルでより明快な形式を選ぶのがほぼ常に正解。

## ささやかな落とし穴

どちらの形式も、`y` が **すべての** シナリオで代入されることを要求します。`when/else` の最後の `else` を忘れたり、`with/select` の `when others` を飛ばしたりすると、コンパイラが警告を出します — そしてシンセサイザは「最後の値を覚えておく」ためにラッチを推論するかもしれず、これはほぼ望まない結果です。これは順序回路モジュールの修正練習で再び出会う、同じラッチの罠です。

## 次にどこで出てくるか

このレッスンの直後に続く 3-to-8 デコーダサンプルで `with/select` を使い、後の信号機 FSM では至るところで `when/else` を使います。どちらも VHDL の基本中の基本です。
