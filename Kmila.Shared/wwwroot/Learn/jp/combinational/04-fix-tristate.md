# 修正:常に駆動してしまうトライステートバッファ

トライステートバッファは切り替え可能な出力。出力イネーブル(`oe`)信号が High のとき、データをバスに通す。`oe` が Low のとき、バスを**解放**する — 他のデバイスが話せるようハイインピーダンス(`'Z'`)を駆動する。

## どこが間違いか

サンプルを開いて本体を見て:

```vhdl
y <= d when oe = '0' else 'Z';
```

声に出して読んで:「`y` は `d`、**`oe` が 0 のとき**、それ以外は `'Z'`」。逆。あなたが欲しいのはイネーブルが **High** のときデータを通し、**Low** のとき解放するバッファ。

## あなたのミッション

- エディタでサンプルを開く。
- 12 行目の条件(`y <=` 代入)を修正。
- シミュレーションを実行し、Waveforms タブで確認:
  - `oe = '0'` のとき `y` は `'Z'` であるべき。
  - `oe = '1'` のとき `y` は `d` に追従すべき。

## なぜトライステートが大切か

トライステートバッファは、複数のドライバが互いをショートさせずに 1 本の線(バス)を共有する方法。FPGA は内部ファブリックにトライステートを持たない — 代わりにマルチプレクサを使う — が、**外部**トライステート(I/O パッド側)は DDR メモリや PCIe エンドポイントがピンを共有する方法として今も使われる。

## 余分:`'X'` に注意

2 つのトライステートバッファが同じバスを同時に異なる値で駆動すると、実回路は煙が出る。シミュレータは波形上で `'X'`(不明)として表示する。あなたのバッファ 2 つを同じ `y` に配線した小さなテストベンチを作って、何が起きるか見てみよう。
