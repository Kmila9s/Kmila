# 修正:常に駆動してしまうトライステートバッファ

トライステートバッファは、切り替えられる出力だ。出力イネーブル(`oe`)信号が High のとき、データをバスへ通す。`oe` が Low のとき、バスを **解放** する — ハイインピーダンス(`'Z'`)を駆動して、他のデバイスが話せるようにするのだ。これは、9 値ロジックの `'Z'` の値がその存在価値を発揮する、この単元で唯一の場所だ。

## 何が間違っているか

サンプルを開いて、本体を見てみよう。

```vhdl
y <= d when oe = '0' else 'Z';
```

声に出して読んでみよう。「`y` は **`oe` が 0 のとき** `d` に等しく、そうでなければ `'Z'`。」これは逆だ。バッファには、イネーブルが **High** のときにデータを通し、**Low** のときに解放してほしいのだ。

## あなたのミッション

- サンプルをエディタで開く。
- `oe` の意味が正しくなるように、`y <=` 代入の条件を修正する。

```vhdl
y <= d when oe = '1' else 'Z';
```

- シミュレーションを実行し、Waveforms タブで確認する。
  - `oe = '0'` のとき、`y` は `'Z'` であるべきだ。
  - `oe = '1'` のとき、`y` は `d` に追従するべきだ。

## ここで `'Z'` が特別な理由

`'Z'` は 3 番目のロジック *レベル* ではない — 「私は駆動していない」という意味だ。波形では、GTKWave はこれを High でも Low でもない、真ん中に停まった線として表示する。トライステートの要点は、1 本の線に **複数** の潜在的なドライバを持たせ、一度にそのうち 1 つだけをアクティブにできるようにすることだ。これが安全なのは、`std_logic` が *解決可能(resolved)* な型だからだ。一方のドライバが `'Z'` で、もう一方が `'0'` や `'1'` を駆動するとき、解決は強い値を勝たせる。すべてのドライバが `'Z'` なら、線は浮く。

## 補足:`'X'` に注意

2 つのトライステートバッファが、**異なる** 値で同じバスを同時に駆動すると、実際の回路はそれ自身と戦い、過熱する。解決関数はこれを波形上で `'X'`(強い不定)としてモデル化する — イネーブルが重なっているという明らかな赤信号だ。あなたのバッファ 2 つを同じ `y` に配線した小さなテストベンチを作り、両方の `oe` 線を異なる `d` でオンにして、バスが `'X'` になる様子を見てみよう。

## なぜトライステートが重要か(そして今日どこに住んでいるか)

トライステートバッファは、複数のドライバが互いに短絡することなく 1 本の線(バス)を共有するための仕組みだ。あなたが実際にターゲットにするハードウェアについて、重要な注意が一つある。**FPGA はその論理ファブリックの内部にトライステートバッファを持っていない** — 合成は内部トライステートバスをマルチプレクサで自動的に置き換える。トライステートが生き残るのは **I/O パッド** だけで、そこでは双方向ピンがまさにこうして動く。DDR メモリのデータ線、I²C の `sda`、その他の共有バスは、すべてピンのドライバを `oe` でオン・オフする。その双方向パッドは `inout` ポートでモデル化される。

```vhdl
io_pin <= drive_value when oe = '1' else 'Z';  -- パッドを駆動または解放する
read_value <= io_pin;                           -- そこにあるものを常にサンプルする
```

## 覚えておくべきこと

- トライステートは有効なときにデータを通し、無効なとき `'Z'`(解放)を駆動する — `oe` の意味を正しく取ろう。
- `'Z'` は「駆動していない」という意味で、これが多くのドライバに 1 本の解決可能な `std_logic` 線を共有させるものだ。
- 異なる値を持つ 2 つのアクティブなドライバは `'X'` に解決される — 波形で見えるバグだ。
- FPGA の内部ではトライステートは mux になる。本物のトライステートは、双方向ピン(`inout`)のために I/O パッドに住んでいる。
