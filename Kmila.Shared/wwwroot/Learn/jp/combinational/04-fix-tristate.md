# 修正せよ: 常にドライブしてしまうトライステートバッファ

トライステートバッファは、切り替え可能な出力です。出力イネーブル (`oe`) 信号がハイのとき、データをバスに通します。`oe` がローのとき、バスを **解放** します — 他のデバイスが話せるように高インピーダンス (`'Z'`) を駆動します。

## 何が問題か

サンプルを開いて本体を見てください:

```vhdl
y <= d when oe = '0' else 'Z';
```

声に出して読んでみてください: 「`y` は `d` に等しい **`oe` が 0 のとき**、そうでなければ `'Z'`」。これは逆です。バッファはイネーブルが **ハイ** のときにデータを通し、**ロー** のときに解放すべきです。

## ミッション

- エディタでサンプルを開く。
- 12 行目の条件 (`y <=` の代入) を修正する。
- シミュレーションを実行し、Waveforms タブで検証する:
  - `oe = '0'` のとき、`y` は `'Z'` であるべき。
  - `oe = '1'` のとき、`y` は `d` を追従するべき。

## なぜトライステートが重要か

トライステートバッファは、複数のドライバが互いを短絡させずに 1 本の配線(バス)を共有する方法です。FPGA の内部ファブリックにはトライステートがありません — 代わりにマルチプレクサを使います — しかし **外部** トライステート(I/O パッド部)は、DDR メモリや PCIe エンドポイントがピンを共有するための方法として今でも使われています。

## おまけ: `'X'` に注意

2 つのトライステートバッファが同じバスを同時に異なる値で駆動すると、実回路なら煙を出します。シミュレータはこれを波形上で `'X'` (不定)として示します。2 つのバッファを同じ `y` に接続した小さなテストベンチを作って、何が起こるかを観察してみてください。
