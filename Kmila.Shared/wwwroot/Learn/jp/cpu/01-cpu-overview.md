# CPU が 1 命令を実行する仕組み

どんな CPU の中を見ても — 小さな 8 ビットマイコンから現代の GPU シェーダコアまで — 同じ 5 つのステージが、同じ 5 つの仕事をしている:

```mermaid
flowchart LR
    IF["IF<br/>フェッチ"] --> ID["ID<br/>デコード"] --> EX["EX<br/>実行"] --> MEM["MEM<br/>メモリ"] --> WB["WB<br/>ライトバック"]
```

## 5 つの古典的ステージ

**IF(命令フェッチ)。** Program Counter (PC) が指すアドレスのプログラムメモリから次の命令を読む。次サイクルで次の命令を指せるよう PC をインクリメント。

**ID(デコード)。** 命令ワードを開く。**opcode**(何の操作?)と**オペランドフィールド**(どのレジスタ?どの即値?)に分ける。

**EX(実行)。** オペランドを ALU に流す。`ADD R0, R1` なら、EX はレジスタファイルから R0 と R1 を読み、ALU に「add」と告げ、結果をラッチする。`JUMP addr` なら、EX が新しい PC を計算する。

**MEM(メモリ)。** 命令がロードかストアなら、ここでデータメモリと話す。レジスタ間命令ではこのステージは素通り — でもステージは常にあり、すべての命令が同じパイプライン深さになるようにする。

**WB(ライトバック)。** 結果がついに行き先に届く — 算術なら register、ジャンプなら PC、ストアならメモリセル。

## シングルサイクル vs マルチサイクル vs パイプライン

同じ 5 つの仕事は、シリコン上で 3 つの異なる並べ方ができる:

**シングルサイクル。** 5 ステージすべてを 1 クロック周期内に組合せ的に実行。Pro:シンプル。Con:クロックを、最長命令(通常はロード)が *すべて* を 1 ティックで伝播するくらい遅くしなければならない。MIPS の教科書例はみなシングルサイクル。

**マルチサイクル。** 1 ステージ 1 クロック。命令はステージを進む間、状態レジスタに座る。Pro:シングルサイクルより速いクロック(各ステージが独自の短いクリティカルパスを持つ)。Con:命令あたり 5 サイクル。

**パイプライン。** 5 命令が同時に飛んでいて、それぞれ違うステージにいる。Pro:1 クロックごとに 1 つ新しい命令が完了する。だからスループット ≈ シングルサイクルだがクロックははるかに速い。Con:ハザード(データ、制御、構造)— コンピュータアーキテクチャの授業の残りはまさにそれに費やされる。RISC-V コア、ARM Cortex-M、AMD Zen — すべてパイプライン。

## このカリキュラムの CPU プロジェクト

最初の CPU は扱いやすさのために **シングルサイクル**。すべてが 1 クロック周期内に組合せ的に起きる:

- PC が 16 バイトの ROM をアドレス指定する。
- フェッチされたバイトは opcode ニブルでもあり即値ニブルでもある。
- デコード + 実行 + ライトバックすべてが、次の立ち上がりクロックエッジ(新しい PC と新しい R0 をラッチする)の前に起きる。

## 実装する ISA

4 命令、4 ビット opcode + 4 ビット即値:

| Opcode | ニーモニック   | セマンティクス                  |
|--------|---------------|--------------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`         |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)`    |
| `0010` | `JUMP addr`   | `PC <= addr`                   |
| `1111` | `HALT`        | PC と R0 を凍結                |

すでに手で走らせられるプログラム:

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## これが何をもたらすか

雛形が動き始めれば、あなたは **プログラム可能な機械** を手にしている。ROM 内のバイトを変える — CPU が走らせるプログラムが変わる。これが根本的なトリック:同じハードウェア、違うメモリ内容、違う挙動。

ここから育てられる:

- レジスタを増やす(R0..R3)。
- 条件ジャンプ(`JZ`、`JNZ`)を加え、プログラムが分岐できるようにする。
- RAM モジュール(Memories モジュールのものを再利用)からロード/ストア。
- すべてをパイプライン化する。

この 4 命令マシンから完全な RV32I RISC-V コアまでの道のりは長いが、各ステップはあなたが今から作る同じパターンの繰り返しにすぎない。
