# CPU が 1 命令を実行する仕組み

どんな CPU の中を覗いても — 小さな 8 ビットマイコンから現代の GPU シェーダコアまで — 同じ 5 つのステージが、同じ 5 つの仕事をしているのが見つかる:

```mermaid
flowchart LR
    IF["IF<br/>fetch"] --> ID["ID<br/>decode"] --> EX["EX<br/>execute"] --> MEM["MEM<br/>memory"] --> WB["WB<br/>writeback"]
```

## 5 つの古典的なステージ

**IF(命令フェッチ)。** Program Counter(PC)が指すアドレスのプログラムメモリから、次の命令を読む。次のサイクルで続く命令を指せるよう、PC をインクリメントする。

**ID(デコード)。** 命令ワードを開く。それを **opcode**(どの操作か?)と **オペランドフィールド**(どのレジスタ? どの即値?)に分ける。

**EX(実行)。** オペランドを ALU に流し込む。`ADD R0, R1` 命令なら、EX はレジスタファイルから R0 と R1 を読み、ALU に「加算せよ」と告げ、結果をラッチする。`JUMP addr` 命令なら、EX が新しい PC を計算する。

**MEM(メモリ)。** 命令がロードかストアなら、ここでデータメモリと話す。レジスタ間命令では、このステージは素通りだ — それでもステージは常にそこにあり、すべての命令が同じパイプライン深さを持つようにする。

**WB(ライトバック)。** 結果がついに行き先に届く — 算術ならレジスタ、ジャンプなら PC、ストアならメモリセルだ。

## シングルサイクル vs マルチサイクル vs パイプライン

同じ 5 つの仕事は、シリコン上で 3 通りに並べられる:

**シングルサイクル。** 5 つのステージすべてを 1 クロック周期内に組合せ的に実行する。長所:単純。短所:クロックは、最も長い命令(たいていはロード)が 1 ティックで *すべて* を伝播し終えるくらい遅くしなければならない。教科書的な MIPS の例はどれもシングルサイクルだ。

**マルチサイクル。** 1 ステージにつき 1 クロックサイクル。命令はステージを移動する間、状態レジスタに座っている。長所:シングルサイクルより速いクロック(各ステージが独自の短いクリティカルパスを持つ)。短所:命令あたり 5 サイクルかかる。

**パイプライン。** 5 つの命令が同時に飛んでいて、それぞれ違うステージにいる。長所:1 クロックごとに新しい命令が 1 つ完了するので、スループットは ≈ シングルサイクルだが、クロックははるかに速い。短所:ハザード(データ、制御、構造) — 計算機アーキテクチャのコースの残りは、まさにそれに費やされる。RISC-V コア、ARM Cortex-M、AMD Zen — すべてパイプラインだ。

## RISC、CISC、そしてステージがこんなにきれいな理由

あの 5 つのきれいなステージは偶然ではない — 命令セットが規則的になるよう設計されたときに得られるものだ。それが、ESCOM のコースが土台にしている **RISC**(Reduced Instruction Set Computer、縮小命令セットコンピュータ)の哲学だ:

- **固定幅の命令**(どの命令も同じビット数)なので、フェッチとデコードが簡単になる。
- **ロード/ストアアーキテクチャ** — メモリに触れるのは専用のロード命令とストア命令だけで、算術はレジスタ間で行う。だから MEM がきれいな独立したステージになる。
- **多数の汎用レジスタ** があるので、コンパイラは値をメモリに退避させずレジスタファイルに保つ。

**CISC**(Complex Instruction Set Computer、複雑命令セットコンピュータ、例:x86)は反対の賭けをする:可変長の命令、メモリを読み *ながら* 計算もする 1 命令、数百のアドレッシングモード。命令あたりは強力だが、きれいにパイプライン化するのははるかに難しくなる。現代の x86 チップは、実際には各複雑命令を内部で RISC 風のマイクロオペに砕いている。

もう 1 つ名前を挙げておく価値のある区別:**ノイマン型** の機械はプログラムとデータを 1 つのメモリに置き(バスが 1 本で単純だが、コードとデータがそれを奪い合う)、**ハーバード型** の機械は命令メモリとデータメモリを分ける。これこそが、シングルサイクルやパイプラインのコアが命令フェッチ *と* データアクセスを同じティックで行えるようにしているものだ。これから作る CPU は事実上ハーバード型だ — コード用の ROM と、データ用の別経路だ。

## 命令フォーマット

デコードが簡単なのは、各命令のフィールドが固定の位置に収まっているからにほかならない。古典的な RISC(MIPS 風、ESCOM が使うモデル)には 3 つのフォーマットがある:

- **R 形式** — レジスタ間の ALU 操作:`opcode | rs | rt | rd | shamt | funct`。2 つのソースレジスタ、1 つのデスティネーション、シフト量、関数セレクタ。
- **I 形式** — 即値 / ロード / ストア / 分岐:`opcode | rs | rt | immediate`。16 ビットの即値は定数またはアドレスオフセット。
- **J 形式** — ジャンプ:`opcode | address`。遠いターゲットに届くための大きなアドレスフィールド。

下のおもちゃの ISA は、この考え方の 2 フィールド版の親戚だ:4 ビットの opcode と 4 ビットの即値。原理は同じで、より小さいだけだ。

## このカリキュラムの CPU プロジェクト

最初の CPU は、扱いやすさのために **シングルサイクル** にする。すべてが 1 クロック周期の中で組合せ的に起こる:

- PC が 16 バイトの ROM をアドレス指定する。
- フェッチされたバイトは、opcode ニブルでもあり即値ニブルでもある。
- デコード + 実行 + ライトバックはすべて、次の立ち上がりクロックエッジ(新しい PC と新しい R0 をラッチする)の前に起こる。

## 実装する ISA

4 つの命令、4 ビットの opcode + 4 ビットの即値:

| Opcode | ニーモニック   | セマンティクス                  |
|--------|---------------|--------------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`         |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)`    |
| `0010` | `JUMP addr`   | `PC <= addr`                   |
| `1111` | `HALT`        | PC と R0 を凍結する            |

すでに手で走らせられるプログラム:

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## これが何をもたらすか

雛形が動き始めれば、あなたは **プログラム可能な機械** を手にしている。ROM の中のバイトを変えれば — CPU が走らせるプログラムが変わる。これが根本的なトリックだ:同じハードウェア、違うメモリ内容、違う挙動。

ここから育てられる:

- レジスタを増やす(R0..R3)。
- 条件ジャンプ(`JZ`、`JNZ`)を加え、プログラムが分岐できるようにする。
- RAM モジュール(Memories モジュールのものを再利用)からロード/ストアする。
- すべてをパイプライン化する。

この 4 命令の機械から完全な RV32I RISC-V コアまでの道のりは長いが、どのステップも、これから作る同じパターンの繰り返しにすぎない。

## これらすべてを操るもの:制御ユニット

データパス(PC、ROM、レジスタファイル、ALU、メモリ)は配管だ。**制御ユニット** は、サイクルごとに正しいバルブを開けるものだ。opcode を読み、制御信号を駆動する:どの ALU 操作か、このサイクルにレジスタファイルは書き込むか、メモリは読むか書くか、次の PC はどこから来るか。作り方は 2 つある:

- **ハードワイヤード制御** — opcode が組合せ論理(または小さな状態機械)に入り、直接信号を生み出す。高速で、きれいな RISC には自然な選択。あなたの雛形が opcode に対する `case` でやっているのがこれだ。
- **マイクロコード制御** — 各命令が、マイクロコード ROM に格納された短い *マイクロ命令* のプログラムで、それが制御信号を 1 歩ずつ繰り出す。柔軟で、歴史的には CISC 機械がその複雑さを飼いならしてきた方法だが、速度を犠牲にする。ESCOM のシラバスは両方を名指ししている(microinstrucciones、memorias de microcódigo)ので、区別できるようにしておこう。

その隣に座るのが **ステータスレジスタ** だ — ALU が生んだフラグ(zero、carry、overflow、negative)だ。条件分岐とは、制御ユニットがそれらのフラグの 1 つを調べて次の PC を決めることにほかならない。

## 覚えておくべきこと

- どんな CPU も、大小を問わず同じループを走らせる:フェッチ、デコード、実行、メモリ、ライトバック。
- それらのステージは、シングルサイクル(単純、クロックが遅い)、マルチサイクル(クロックが速いが命令あたり数サイクル)、またはパイプライン(重ね合わせ、スループット最高)にできる。
- RISC は命令を固定幅かつロード/ストアに保つことで、デコードとパイプライン化をきれいに保つ。CISC はそれを手放して命令あたりの力を得る。
- データパスはデータを動かし、制御ユニット(ハードワイヤードまたはマイクロコード)は opcode とステータスフラグを使って、何をどこへ動かすかを決める。
