# CPU が 1 つの命令を実行する方法

どんな CPU でも — 小さな 8 ビットマイクロコントローラから最新の GPU シェーダコアまで — 内部を覗くと、同じ 5 つのステージが同じ 5 つの仕事をしているのが見えます:

```mermaid
flowchart LR
    IF["IF<br/>fetch"] --> ID["ID<br/>decode"] --> EX["EX<br/>execute"] --> MEM["MEM<br/>memory"] --> WB["WB<br/>writeback"]
```

## 古典的な 5 ステージ

**IF (Instruction Fetch: 命令フェッチ)**。プログラムカウンタ (PC) のアドレスから、プログラムメモリの次の命令を読み込みます。次のサイクルで次の命令を指すように PC をインクリメントします。

**ID (Decode: デコード)**。命令語を解析します。**オペコード** (どの演算か?) と **オペランドフィールド** (どのレジスタか? 即値は何か?) に分割します。

**EX (Execute: 実行)**。オペランドを ALU に送ります。`ADD R0, R1` 命令では、EX はレジスタファイルから R0 と R1 を読み、ALU に「加算」と指示し、結果をラッチします。`JUMP addr` 命令では、EX は新しい PC を計算します。

**MEM (Memory: メモリ)**。命令がロードまたはストアなら、ここでデータメモリと通信します。レジスタ間命令では、このステージは素通しです — しかし、すべての命令が同じパイプライン深さを持つようにステージは常に存在します。

**WB (Writeback: ライトバック)**。結果がついに宛先に届きます — 算術ならレジスタ、ジャンプなら PC、ストアならメモリセル。

## シングルサイクル vs マルチサイクル vs パイプライン

同じ 5 つの仕事は、シリコンで 3 通りの方法で配置できます:

**シングルサイクル。** 5 つのステージすべてが 1 クロック周期内で組合せ的に実行されます。利点: 単純。欠点: クロックは最も長い命令(通常はロード)が1ティックで *すべて* を伝播するのに十分なほど遅くなければならない。すべての単純な MIPS の教育例はシングルサイクルです。

**マルチサイクル。** 1 クロックサイクルにつき 1 ステージ。命令はステージ間を移動する間、状態レジスタに座っています。利点: シングルサイクルより高速なクロック(各ステージが独自の短いクリティカルパスを持つ)。欠点: 命令ごとに 5 サイクル。

**パイプライン。** 5 つの命令が同時に実行中で、それぞれ異なるステージにいます。利点: クロックごとに新しい命令が 1 つリタイアするので、はるかに高速なクロックでスループット ≈ シングルサイクル。欠点: コンピュータアーキテクチャコースの残り全体が捧げられているハザード(データ、制御、構造)。RISC-V コア、ARM Cortex-M、AMD Zen — すべてパイプライン。

## このカリキュラムの CPU プロジェクト

最初の CPU は扱いやすくするため **シングルサイクル** です。1 クロック周期内ですべてが組合せ的に起こります:

- PC が 16 バイトの ROM をアドレッシングする。
- フェッチされたバイトがオペコードニブルと即値ニブルの両方である。
- デコード + 実行 + ライトバックはすべて、新しい PC と新しい R0 をキャプチャする次のクロック立ち上がりエッジの前に起こる。

## 実装する ISA

4 つの命令、4 ビットオペコード + 4 ビット即値:

| Opcode | ニモニック    | 意味                        |
|--------|---------------|-----------------------------|
| `0000` | `LOAD R0, #i` | `R0 <= zero_extend(i)`      |
| `0001` | `ADD  R0, #i` | `R0 <= R0 + zero_extend(i)` |
| `0010` | `JUMP addr`   | `PC <= addr`                |
| `1111` | `HALT`        | PC と R0 を凍結              |

すでに手で実行できるプログラム:

```
0: 03   LOAD R0, #3       -- R0 = 3
1: 14   ADD  R0, #4       -- R0 = 7
2: 12   ADD  R0, #2       -- R0 = 9
3: F0   HALT
```

## これが得られるもの

スキャフォールドが動くと、**プログラマブルな機械** が手に入ります。ROM のバイトを変えると — CPU が実行するプログラムが変わります。それが根本的なトリックです: 同じハードウェア、メモリ内の異なる内容、異なる振る舞い。

ここから成長できます:

- レジスタを増やす (R0..R3)。
- 条件ジャンプ (`JZ`、`JNZ`) を追加して、プログラムが分岐できるようにする。
- RAM モジュールからのロード/ストアを追加する(メモリモジュールのものを再利用)。
- 全体をパイプライン化する。

この 4 命令の機械から完全な RV32I RISC-V コアまでの道のりは長いですが、各ステップは、あなたが今から作ろうとしているパターンのさらに多くの繰り返しに過ぎません。
