# プロジェクト:フラグ付き 8 ビット ALU

**算術論理ユニット**(ALU)は、あらゆる CPU の脈打つ心臓だ。2 つのオペランドと opcode を与えると、結果と、何が起きたかを記述する一握りのフラグ(オーバーフローしたか? 結果はゼロか? など)を返してくれる。

## 何を作るか

次の操作を持つ 8 ビット ALU だ:

| Opcode | 名称    | 式                        |
|--------|---------|---------------------------|
| `000`  | ADD     | `y = a + b`               |
| `001`  | SUB     | `y = a - b`               |
| `010`  | AND     | `y = a and b`             |
| `011`  | OR      | `y = a or  b`             |
| `100`  | XOR     | `y = a xor b`             |
| `101`  | SHL     | `y = a を左に 1 ビットシフト` |
| `110`  | SHR     | `y = a を右に 1 ビットシフト` |
| `111`  | PASS_A  | `y = a`(パススルー)        |

加えて、2 つのフラグ出力:

- `zero` — `y` がすべてゼロのとき High
- `carry` — ADD/SUB のキャリーアウト。それ以外では `'0'` を駆動

ESCOM の *Arquitectura de Computadoras*(計算機アーキテクチャ)コースでは、これはトピック 3.1、シングルサイクル RISC プロセッサの最初の機能ブロックだ。今ここできれいに作っておけば、あとでそのままデータパスに落とし込める。

## その下にある加算器

ADD と SUB は VHDL の 1 行(`a + b`)に見えるが、その `+` のためにシンセサイザが組み立てるハードウェアにこそ、面白いエンジニアリングが宿っている。コースでは 2 つの古典的な構造を比較することを求めている。

**リプルキャリー加算器。** 8 個の全加算器を鎖のようにつなぎ、各段のキャリーアウトを次の段のキャリーインに送り込む。小さくて素直だが、最上位の和ビットが確定する前に、キャリーがビット 0 からビット 7 まで *さざ波のように伝わる(ripple)* 必要がある — だから最悪遅延はワード幅に比例して大きくなる。8 ビット加算器なら、8 段分の全加算器遅延が端から端まで積み重なる。

**キャリー先見加算器(CLA)。** さざ波を待つ代わりに、各キャリーを入力から直接計算する。ビットごとに 2 つの信号を定義する:

```
generate:  g(i) = a(i) and b(i)      -- このビットは自前でキャリーを作る
propagate: p(i) = a(i) xor b(i)      -- このビットは入ってきたキャリーを通す
```

すると、どのキャリーも `c(i+1) = g(i) or (p(i) and c(i))` となり、これを展開してキャリーを次々にではなく並列に生成する。遅延は幅に対してほぼ一定になるが、ゲート数が増える代償がある。これがシラバスが、縦続接続の「acarreo en cascada」(カスケードキャリー)リプル設計と対比させる「acarreo anticipado」(先見キャリー)だ。

このプロジェクトではどちらも手で組む必要はない — `a + b` と書けば、FPGA ツールが最適化されたキャリーチェーンを選ぶ(Artix-7 のファブリックには専用の高速キャリー論理すらある)。要点は、その `+` がどんなトレードオフを表しているのかを *理解する* ことだ:面積 対 速度だ。

## フラグを正しくする

フラグは、初心者が静かに点を落とすところだ。なぜなら **キャリー** と **オーバーフロー** は別物だからだ:

- **キャリー(C)** は、*符号なし* 加算の最上位からこぼれ落ちるビットだ。`a + b` の 9 ビット目だ。
- **オーバーフロー(V)** は、*符号付き*(2 の補数)の結果がもう 8 ビットに収まらないことを知らせる。きれいなルール:`V = carry_into_MSB xor carry_out_of_MSB`。言い換えれば、同じ符号の 2 つのオペランドが反対の符号の結果を生んだら、オーバーフローが起きている。

両方を一度に扱う VHDL のきれいな手は、9 ビットの空間で足すことだ:

```vhdl
signal ext : unsigned(8 downto 0);
...
ext   <= ('0' & unsigned(a)) + ('0' & unsigned(b));  -- 9 ビット加算
result <= std_logic_vector(ext(7 downto 0));
cout   <= ext(8);                                     -- キャリーフラグ
```

SUB については、2 の補数では減算が `a + (not b) + 1` であることを思い出そう。だから `15 - 15` は結果がゼロでも内部的にキャリーアウト `1` を生む — まさにそのため、多くの ISA は減算のキャリーを *ボロー* として扱う(C = not borrow)。使う規約を、付属のテストベンチが期待するものと一貫させよう。

## 雛形が与えるもの

スタータは、entity、`result` と `cout` 信号、そして ADD と SUB をすでに処理する `process(op, a, b)` のシェルを宣言している。あなたの仕事は、`case` 文の残り 6 つの分岐を埋めることだ。

## ヒント

- **AND / OR / XOR** はそれぞれ 1 行だ — ビット単位の結果を代入するだけ:

  ```vhdl
  when "010" => result <= a and b;
  ```

- **SHL** と **SHR** は `'0'` でパディングする:

  ```vhdl
  when "101" => result <= a(6 downto 0) & '0';
  when "110" => result <= '0' & a(7 downto 1);
  ```

- **PASS_A** は、`a` を `result` にコピーするだけだ。

論理演算では `cout <= '0'` を駆動するのを忘れずに — プロセスの先頭で一度やっておけば、それを上書きしない分岐はそのデフォルトを継承する。便利だが、裏を返せば、ある分岐が **ゼロでない** キャリーを欲しいときには明示する必要があるということだ。

## 受け入れ基準

付属の config のスティミュラスで:

| 時刻 | op    | a          | b          | 期待する `y` | `carry` | `zero` |
|------|-------|------------|------------|--------------|---------|--------|
|  0   | `000` | `00001111` | `00000101` | `00010100`   | `0`     | `0`    |
| 20   | `001` | `00001111` | `00001111` | `00000000`   | `0`     | `1`    |
| 40   | `010` | `00001111` | `00001111` | `00001111`   | `0`     | `0`    |
| 60   | `101` | `10110000` | n/a        | `01100000`   | `0`     | `0`    |
| 80   | `111` | `10110000` | n/a        | `10110000`   | `0`     | `0`    |

## さらに進めるなら

- **signed**(符号)フラグを追加する(2 の補数 SUB で負の結果になったとき)。
- **rotate**(回転)opcode を追加する — SHL と同じだが、最上位ビットがビット 0 に巻き戻る。
- **multiply**(乗算)opcode を追加し、2 つの別々の出力ポートに 16 ビットの結果を出す。多くの小型 FPGA はこのための専用 DSP ブロックを持っている — 再合成するときはリソース使用率に注意しよう。

この ALU は Expert レベルの CPU プロジェクトの直接の構成要素だ — この設計をきれいに保っておこう — そこで配線することになる。

## 覚えておくべきこと

- ALU はオペランドを入れ、結果とフラグを出すものだ。opcode が、その 1 つのブロックがどの操作を行うかを選ぶ。
- あなたが書く `+` は本物の選択を隠している:リプルキャリー(小さく、遅く、遅延が幅とともに増える)対 キャリー先見(大きく、速く、遅延がほぼ一定)で、generate/propagate 項を使う。
- **キャリー ≠ オーバーフロー。** キャリーは符号なしの 9 ビット目、オーバーフローは `carry_in(MSB) xor carry_out(MSB)` で、符号付きの値でのみ意味を持つ。
- プロセスの先頭ですべてのフラグに妥当なデフォルトを設定し、本当に必要な分岐でだけ上書きしよう — それが、ラッチとケースの抜けを避ける方法だ。
