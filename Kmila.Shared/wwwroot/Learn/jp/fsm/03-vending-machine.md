# プロジェクト:コイン投入式自動販売機

これがあなたの最初の本格的なプロジェクトだ。仕様は固定で、スタータコードが配管を渡してくれる。あなたの仕事は、それを完成させるロジックを書くことだ。

## 何を作るか

顧客が投入した金額を追跡し、合計が 25¢ に達したら商品を出す(1 本の出力パルス `dispense`)FSM だ。入力は次のとおりだ:

- `nickel` — 「5¢ 硬貨が今落ちた」を意味する 1 サイクルのパルス
- `dime`   — 「10¢ 硬貨が今落ちた」を意味する 1 サイクルのパルス
- `clk`、`reset`

そして出力:

- `dispense` — ≥ 25¢ に達したとき、ちょうど 1 クロックサイクル分だけ High になるパルス
- `change`   — 合計が 25¢ **を超えた** 場合に、`dispense` と並んで 1 サイクル分 High になるパルス(つまり機械がお釣りを返す必要があるとき)

## これをモデル化する 2 つの方法

自動販売機は典型的な FSM で、それを記述する誠実な方法が 2 つある:

- **明示的な状態。** 到達しうる合計をすべて列挙し — `S0, S5, S10, S15, S20` — 硬貨ごとに遷移を描く。これは教科書的なアプローチで、小さな硬貨の集合なら手でやるやり方だ。状態遷移図が一目瞭然になるが、硬貨を増やしたり価格を上げたりすると爆発する。
- **アキュムレータ(データパス)スタイル。** 合計を小さなレジスタに持ち、価格と比較する。行数が少なく、どんな価格にもスケールし、スタータコードが使っている形だ。`total` レジスタを状態、比較器を次状態論理だと考えることができる。

どちらにしても、`dispense` は *この* サイクルに到着した硬貨に依存するので、**Mealy** 出力のように振る舞う — 1 サイクル待つのではなく、販売条件が真になったのと同じサイクルで反応する。

## スタータが与えるもの

entity と `total` アキュムレータは配線済みだ。`nickel` パルスごとに 5、`dime` パルスごとに 10 が加算される。しかしスタータは常に `dispense = '0'` と `change = '0'` を駆動する。**ここを変えるのがあなたの仕事だ。**

```vhdl
process(clk, reset)
begin
  if reset = '1' then
    total <= (others => '0');
  elsif rising_edge(clk) then
    if    nickel = '1' then total <= total + 5;
    elsif dime   = '1' then total <= total + 10;
    end if;
  end if;
end process;

dispense <= '0';  -- TODO
change   <= '0';  -- TODO
```

## 推奨するアプローチ

1. **販売条件を検出する。** 立ち上がりエッジごとに、今回の硬貨を加算した *後* に `total >= 25` かどうかを確認する。(注意:前サイクルの値ではなく、*新しい* 合計を計算する必要がある。)
2. **`dispense` をちょうど 1 サイクル分パルスする。** コツ:販売を検出したらパルスを立て、同時に `total` をゼロに戻す。`total` が同じエッジでクリアされるので、次サイクルには条件が偽になり、パルスは自然に 1 サイクル幅になる。
3. **`change` を計算する。** 販売の瞬間の合計が > 25 だったら、`change` もパルスする。

「次の合計」をプロセス内の `variable` として計算すると、判定が前サイクルのレジスタ値ではなく最新の値を使うようになる:

```vhdl
process(clk, reset)
  variable next_total : unsigned(5 downto 0);
begin
  if reset = '1' then
    total    <= (others => '0');
    dispense <= '0';
    change   <= '0';
  elsif rising_edge(clk) then
    next_total := total;
    if    nickel = '1' then next_total := total + 5;
    elsif dime   = '1' then next_total := total + 10;
    end if;

    if next_total >= 25 then
      dispense <= '1';
      if next_total > 25 then change <= '1'; else change <= '0'; end if;
      total    <= (others => '0');
    else
      dispense <= '0';
      change   <= '0';
      total    <= next_total;
    end if;
  end if;
end process;
```

注目すべき点が 2 つある。`variable` は `:=` で代入され、プロセス内で **即座に** 更新される。だからこそ `next_total` にはこのサイクルの硬貨がすでに含まれているのだ — signal(`<=`)ならプロセスが中断するまで更新されない。そして `dispense`、`change`、`total` はすべてクロック付きプロセスの中で駆動されるので、**レジスタに入る** — パルスはクロックエッジに揃い、グリッチしない。

## 気をつけること

- **ビット幅。** `total + 10` はリセットが発火する前に 30 に達しうるので、レジスタは少なくとも 6 ビットにしよう — `unsigned(5 downto 0)` なら 0〜63 を余裕をもって保持できる。狭すぎるベクタは黙って折り返す。
- **両方の硬貨が同時に来たとき。** `if … elsif` では `nickel` と `dime` が同時に来ても nickel しか数えない。それが許容できるのか、仕様上のエラーなのかを決めよう。
- **`total` のクリアを忘れること。** `dispense` をパルスしてもアキュムレータをゼロにしないと、別の硬貨で合計が変わるまで機械は毎サイクル「販売」を続けてしまう。販売エッジでクリアすることが、パルスを 1 サイクル幅にしているのだ。

## 受け入れ基準

| 投入シーケンス        | 期待される動作                |
|----------------------|-------------------------------|
| nickel 5 枚          | `dispense=1, change=0`        |
| dime 2 + nickel 1    | `dispense=1, change=0`        |
| dime 3(= 30¢)       | `dispense=1, change=1`        |
| nickel 2 + dime 1    | 販売なし(20¢ のみ)          |

## さらに進めるなら

- 商品を出さずに `total` をゼロにする **払い戻し** ボタンを追加する。
- **quarter**(25¢)硬貨に対応する — 即座に商品を出すべきだ。
- 売れた商品数を別の 8 ビットカウンタで追跡し、出力として可視化する。これは実際の自動販売機が上流に送るたぐいのフィードバックだ。

## コースとのつながり

これは単元 II の *aplicaciones con autómatas y lenguaje de descripción de hardware* だ:振る舞いから仕様が決まる決定的な順序機械を、HDL で記述する。アキュムレータ + 比較器という形は、単元 V への穏やかな導入でもある。そこでは設計を **データパス**(`total` レジスタと加算器)と、それを駆動する **制御** オートマトンに明示的に分割する。

## 覚えておくべきこと

- 自動販売機は FSM だ。明快さのために明示的な状態でモデル化するか、スケールのためにアキュムレータレジスタでモデル化する。
- 「次の合計」には `variable`(`:=`)を使い、販売判定に今到着した硬貨を含めよう。
- 販売エッジでアキュムレータをクリアして 1 サイクルのパルスを作る — レジスタ付き出力がパルスをきれいに保つ。
- 到達しうる最大値に合わせてベクタ幅を決め、入力が同時に来たときの動作を最初に決めておこう。
