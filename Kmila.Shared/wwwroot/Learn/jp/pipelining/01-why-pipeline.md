# なぜ CPU をパイプライン化するのか?

前のトラックのシングルサイクル 8 ビット CPU は動くが、実ハードウェアで非常に重要な 1 次元で制限される:**クロック周波数**。

## シングルサイクルの天井

シングルサイクル設計では、クロック周期は最も長いクリティカルパス命令が完全に伝播できる長さでなければならない:フェッチ → デコード → レジスタ読み出し → ALU → メモリ → ライトバック、すべて組合せ的に。最長パスが 20 ns なら、最大クロックは 50 MHz。それで終わり。

## パイプライン化はそのパスを分割すること

パスをレジスタで区切られた N 段に分ける:

```
  [IF] → [ID] → [EX] → [MEM] → [WB]
    ^      ^      ^       ^       ^
    +------+------+-------+-------+
         段間のレジスタ
```

クロックはもはやパス全体ではなく、最も長い*段*が完了する長さだけでよい。5 段、各々 ~4 ns なら 250 MHz のクロックになる。スループットは 1 命令 / 20 ns から 1 命令 / 4 ns へ — 概念上はタダで **5 倍の高速化**。

## ハザード — その対価

実際には 5 倍はもらえない。3 種類の衝突:

- **データハザード** — 命令 N+1 が、命令 N がまだ書き込んでいるレジスタを読む。解決策:フォワーディング経路またはストールサイクル。
- **制御ハザード** — 命令 N が分岐で、実行するか判明する前に N+1 をすでにフェッチ済み。解決策:分岐予測またはパイプラインフラッシュ。
- **構造ハザード** — 2 つの段が同じ物理リソース(例:1 つのメモリポート)を必要とする。解決策:リソースを複製するか直列化する。

本モジュールの以降のレッスンでは、カリキュラムの 8 ビット CPU 上で 1 つずつ解決策を実装する。フォワーディングから始める。

## 覚えておくべきこと

- パイプラインは**命令あたりのレイテンシ**(高い)を**スループット**(はるかに高い)と引き換える。
- クロックの高速化は最も短い段ではなく、最も長い段で決まる。
- ハザードはサイクルを消費し、その対策はゲートを消費する。実 CPU 設計はこのトレードオフを大規模に行うこと。
