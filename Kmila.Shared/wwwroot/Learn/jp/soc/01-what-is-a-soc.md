# System-on-Chip とは何か?

前のトラックの 8 ビット CPU は単独で動く。計算はするが、外の世界とは話さない。**System-on-Chip** はその次のサイズ:CPU と一握りの周辺機器、そしてそれらをつなぐファブリックがすべて同じダイ上にある。

## 必須の 3 つの部品

拡張された Kmila CPU から、500 万ドル規模の Apple A シリーズまで、あらゆる SoC は次のように要約できる:

1. **1 つ以上の処理エレメント** — CPU、DSP、GPU、アクセラレータ。
2. **メモリ** — オンチップ SRAM、block RAM、ときにはオフチップ DDR。
3. **インターコネクト** — (1) が (2) や周辺機器と話せるようにする線と調停。

インターコネクトは「ただの RTL」ではなくなり、アーキテクチャ的になる部分。誰がいつ話せるか、何件のトランザクションが同時に飛んでいてよいか、任意のリクエストがどれくらい速く完了できるかを規定する。

## よく使われるインターコネクトプロトコル

業界は数種類に落ち着いている:

| プロトコル     | ベンダ    | どこで見るか                                            |
|----------------|-----------|---------------------------------------------------------|
| AXI4 / AXI4-Lite| ARM      | RISC-V コア、Xilinx PS/PL 境界、ほぼすべての新 IP       |
| AHB / APB      | ARM       | 古い ARM コア、低速周辺機器                             |
| Avalon MM / ST | Intel     | NIOS-II、Qsys 生成の SoC                                |
| Wishbone       | OpenCores | OpenRISC、多くのオープンソース IP コア                  |

すべて、同じ 3 つのレーンに帰着する:**アドレスチャネル**、**書き込みデータチャネル**、**読み出しデータチャネル**。違いはハンドシェイクプロトコル、アウトオブオーダ対応、バーストセマンティクス。

## AXI4-Lite とは実際に何か

AXI ファミリ最も単純なメンバ。バースト、アウトオブオーダ、QoS をすべて取り除けば、5 つの独立したチャネルが残り、それぞれ `valid`/`ready` ハンドシェイクを持つ:

```
  AW  (書き込みアドレス)
  W   (書き込みデータ)
  B   (書き込み応答)
  AR  (読み出しアドレス)
  R   (読み出しデータ)
```

各転送は 1 ビート。各チャネルは相手側が `ready` でなければストールする。それだけ。

## Kmila カリキュラム計画

本モジュールの後のレッスンでは、AXI4-Lite レジスタインタフェースをゼロから構築し、8 ビット CPU とメモリマップド UART の間に配線して、CPU がアドレスに書き込むだけで「印字」できるようにする。これが、現代のあらゆる SoC の中で何が起きているかについての、頭に入る大きさのメンタルモデルを与える。
