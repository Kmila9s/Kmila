# System-on-Chip とは何か?

前のトラックの 8 ビット CPU は単独で動く。計算はするが、外の世界とは話さない。**System-on-Chip** はその次のサイズだ:CPU と一握りの周辺機器、そしてそれらが互いに話せるようにするファブリックが、すべて同じダイの上に載っている。

これが *Sistemas en Chip*(システムオンチップ)コースの前提そのものだ — プロセッサを別々のメモリチップや別々の I/O チップとボード上で配線する代わりに、プロセッサ、そのメモリ、周辺機器を 1 つのデバイスに統合し、その結果をプログラムするのだ。

## 必須の 3 つの部品

拡張された Kmila CPU から 500 万ドル規模の Apple A シリーズまで、あらゆる SoC は次のように煮詰まる:

1. **1 つ以上の処理エレメント** — CPU、DSP、GPU、アクセラレータ。
2. **メモリ** — オンチップの SRAM、block RAM、ときにはオフチップの DDR。
3. **インターコネクト** — (1) が (2) や周辺機器と話せるようにする配線 + 調停。

インターコネクトは、「ただの RTL」であることをやめてアーキテクチャ的に感じられ始める部分だ。誰がいつ話せるか、いくつのトランザクションが同時に飛んでいてよいか、任意のリクエストがどれだけ速く完了できるか、を強制する。

## 処理エレメント:RISC とハーバード

あなたが出会う SoC コアのほとんど — PIC、AVR、ARM Cortex-M、RISC-V — は **RISC**(Reduced Instruction Set Computer、縮小命令セットコンピュータ)だ。RISC とは、1 つのことだけをする、単純で固定幅の小さな命令セットのことで、だからそれらをデコードし実行するハードウェアが小さく速いままに保てる。引き換えに、複雑な操作は 1 命令ではなく複数命令かかる。

それらのコアはたいてい **ハーバード** アーキテクチャだ:プログラムメモリとデータメモリが *別々の* バスに載っている。2 本のバスが独立しているので、コアはデータオペランドを読み書きするのと同時に次の命令をフェッチできる — 1 本の共有バスの 2 倍のメモリ帯域だ。嬉しい副作用として、命令ワードはデータワードの幅と一致している必要がない。たとえば PIC のミッドレンジコアは、8 ビットのデータに対して 14 ビットの命令で動くので、どの命令も 1 ワードに収まる。

(純粋な **ノイマン型** の機械はコードとデータで 1 本のバスを共有する — より単純だが、コードとデータのフェッチがそれを奪い合う。8051 は「修正ハーバード型」の折衷だ。)

## パイプライン

コアは、1 秒あたりより多くの命令を終えるために作業を重ね合わせる。最も単純な形は 2 段 **パイプライン** だ:命令 *N* が実行されている間に、コアはすでに命令 *N+1* をフェッチしている。

```
  cycle:   1        2        3        4
  fetch:  I1       I2       I3       I4
  exec:            I1       I2       I3
```

落とし穴は **分岐** だ。`GOTO`、`CALL`、`RETURN` がプログラムカウンタを変えると、その後ろですでにフェッチ済みの命令は間違いなので、捨てなければならない — パイプラインが *フラッシュ* して詰め直し、1 サイクルを失う。これが、きついループやジャンプの多いコードが、直線的なコードより少し遅く走る理由だ。

## プログラムメモリ、データメモリ、プログラミングモデル

ESCOM の単元は、メモリマップを 2 つの役割に分ける:

- **プログラムメモリ** は命令を保持する(しばしば flash/ROM)。不揮発なので、デバイスは電源投入のたびに同じプログラムで起動する。
- **データメモリ** は変数、スタック、I/O レジスタを保持する(SRAM)。揮発性で、リセットでクリアされる。

その上に重なるのが **プログラミングモデル** だ:プログラマが実際に目にするレジスタとアドレスマップだ。これは汎用レジスタ、特殊機能レジスタ(ステータスフラグ、プログラムカウンタ、スタックポインタ)、そして — SoC にとって決定的に — **メモリマップド周辺レジスタ** を定義する。メモリマップド設計では、周辺機器はいくつかのアドレスのように見える:あるアドレスに 1 バイト書けば UART が送信し、別のアドレスを読めば ADC の結果が得られる。CPU は周辺機器ごとに新しい命令を覚える必要はなく、ただロードとストアをするだけだ。

## よく使われるインターコネクトプロトコル

業界は、そのロード/ストアのファブリックとして、ひと握りの標準に落ち着いている:

| プロトコル        | ベンダ    | どこで目にするか                                 |
|------------------|-----------|--------------------------------------------------|
| AXI4 / AXI4-Lite | ARM       | RISC-V コア、Xilinx の PS/PL 境界、ほぼすべての新しい IP |
| AHB / APB        | ARM       | 古い ARM コア、低速周辺機器                       |
| Avalon MM / ST   | Intel     | NIOS-II、Qsys 生成の SoC                          |
| Wishbone         | OpenCores | OpenRISC、多くのオープンソース IP コア           |

どれも同じレーンに煮詰まる:**アドレスチャネル**、**書き込みデータチャネル**、**読み出しデータチャネル**。違いはハンドシェイクプロトコル、アウトオブオーダ対応、バーストのセマンティクスにある。

## AXI4-Lite とは実際には何か

AXI ファミリの最も単純なメンバだ。バースト、アウトオブオーダ、QoS を取り除くと、それぞれ `valid`/`ready` ハンドシェイクを持つ 5 つの独立したチャネルが得られる:

```
  AW  (アドレス書き込み)
  W   (書き込みデータ)
  B   (書き込み応答)
  AR  (アドレス読み出し)
  R   (読み出しデータ)
```

どの転送も 1 ビートだ。どのチャネルも、相手側が `ready` でなければストールする。それだけだ — だからこそ、手で作るのにちょうどよい大きさなのだ。

## Kmila カリキュラムの計画

後のレッスンでは、AXI4-Lite レジスタインタフェースをゼロから構築し、それをあなたの 8 ビット CPU とメモリマップド UART の間に配線して、CPU がアドレスに書き込むことで「印字」できるようにする。これが、現代のあらゆる SoC の中で何が起きているかについての、実際に頭に収まる大きさのメンタルモデルを与えてくれる。

## 覚えておくべきこと

- SoC = 処理エレメント + メモリ + インターコネクト、すべてが 1 つのダイの上に。
- SoC コアのほとんどは **ハーバード** 分割の **RISC** で、コードとデータが別々のバスを同時に動く。
- 短い **パイプライン** はフェッチと実行を重ね合わせる。**分岐はそれをフラッシュする。**
- プログラムメモリは不揮発のコード、データメモリは揮発性の RAM、**プログラミングモデル** はプログラマが目にするレジスタとアドレスのマップだ。
- 周辺機器は **メモリマップド** だ — CPU は AXI4-Lite のような標準インターコネクト越しに、ふつうのロードとストアでそれらに届く。
