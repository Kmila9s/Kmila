# サンプル: 推論される同期 ROM

すべての FPGA には **ブロック RAM** (BRAM) があります — シンセサイザがあなたのコードに ROM や RAM のパターンを認識したときに使う専用のメモリブロックです。ベンダープリミティブをインスタンス化するのではなく、ツールがどうマッピングすればよいか知っている形状でプレーンな VHDL を書きます。

このサンプルはポータブルで教科書的な ROM パターンです。本格的なシンセサイザ(Xilinx Vivado、Intel Quartus、Lattice Radiant、Yosys)はいずれもこれを認識し、BRAM を自動的に割り当てます。

## パターン

```vhdl
type rom_t is array(0 to 15) of std_logic_vector(7 downto 0);
constant ROM : rom_t := (
  x"00", x"01", x"04", x"09", x"10", x"19", x"24", x"31",
  x"40", x"51", x"64", x"79", x"90", x"A9", x"C4", x"E1"
);

process(clk)
begin
  if rising_edge(clk) then
    data <= ROM(to_integer(unsigned(addr)));
  end if;
end process;
```

これが BRAM フレンドリな ROM になる理由は 3 つ:

1. **ストレージが定数** (`constant ROM : rom_t := (...)`)。データは合成時に固定されます。
2. **読み出しがクロック同期。** 組合せの ROM 読み出しは LUT にしかマップできません — 16 エントリの小さな ROM なら問題ないですが、より大きなものにはシンセサイザが BRAM を割り当てられるクロック同期パターンが必要です。
3. **`addr` は純粋にインデックスとして使われる。** `addr` とメモリ参照の間に高コストな組合せロジックがない。

## なぜこの内容なのか?

例の ROM は `n = 0..15` の `n²` を保持しています。小さなオペランドだけ必要なときに完全な乗算器より高速な、ルックアップテーブルによる二乗ユニットに便利です。以下も保存できます:

- 正弦波テーブル (DDS 信号発生器用)
- CRC 多項式
- プロトコルルックアップテーブル
- キャラクタフォント

## サンプルが行うこと

シミュレーションは `addr` を 5 つの特定の値を通過させます: 0、1、4、8、15。クロックエッジの後、`data` は対応する ROM エントリを 1 サイクル後に表示します(これが同期 ROM の読み出しレイテンシです — アドレスを聞き、**次の** クロックでデータを得ます)。

## 自分でやってみる

- **パラメータ化する。** 固定の 16 エントリサイズを `generic (DEPTH : integer := 16; WIDTH : integer := 8)` に置き換えます。残りのコードは動作し続けるはずです。
- **ファイルから内容を読む。** 実プロジェクトでは `init_from_file()` や別の定数パッケージ経由で ROM 内容をロードします。エラボレーション時に 16 進値のテキストファイルを VHDL に読ませる(`textio` + `hread`)ことを試してみてください。
- **2 つ目の読み出しポートを追加する。** シングルサイクル CPU の命令/データメモリなどに。このパターンはカリキュラムで後ほど CPU プロジェクトで見ることになります。
