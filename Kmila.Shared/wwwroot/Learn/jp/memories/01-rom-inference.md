# サンプル:推論された同期 ROM

すべての FPGA は **block RAM**(BRAM)を持つ — シンセサイザがコード内の ROM/RAM パターンを認識したときに使う専用メモリブロック。ベンダ固有プリミティブを実体化する必要はない;ツールがマップできる形のプレーンな VHDL を書けばよい。

このサンプルは移植可能で教科書的な ROM パターン。本格的なシンセサイザ(Xilinx Vivado、Intel Quartus、Lattice Radiant、Yosys)はみなこれを認識し、自動的に BRAM を割り当てる。

## このパターン

```vhdl
type rom_t is array(0 to 15) of std_logic_vector(7 downto 0);
constant ROM : rom_t := (
  x"00", x"01", x"04", x"09", x"10", x"19", x"24", x"31",
  x"40", x"51", x"64", x"79", x"90", x"A9", x"C4", x"E1"
);

process(clk)
begin
  if rising_edge(clk) then
    data <= ROM(to_integer(unsigned(addr)));
  end if;
end process;
```

これを BRAM フレンドリーな ROM にする 3 つのポイント:

1. **ストレージが定数**(`constant ROM : rom_t := (...)`)。データは合成時に固定。
2. **読み出しがクロック付き**。組合せ ROM 読み出しは LUT にしかマップできない — 16 エントリの小さな ROM なら OK だが、それより大きければシンセサイザに BRAM を割り当てさせるためにクロック付きパターンが必要。
3. **`addr` は純粋にインデックスとして使う**。`addr` とメモリ参照の間に高価な組合せ論理がない。

## なぜこの内容?

サンプル ROM は `n²`(`n = 0..15`)を保持。小さなオペランドだけが必要なときには、完全乗算器より速いルックアップ平方ユニットとして便利。他にも保存できるもの:

- 正弦波テーブル(DDS 信号生成器用)
- CRC 多項式
- プロトコルルックアップテーブル
- 文字フォント

## サンプルが行うこと

sim は `addr` を 5 つの特定値:0、1、4、8、15 で駆動。クロックエッジの 1 サイクル後に `data` が対応する ROM エントリを表示(これが同期 ROM の読み出し遅延 — アドレスを尋ね、**次の**クロックでデータが返る)。

## あなたの番

- **パラメータ化する**。固定の 16 エントリサイズを `generic (DEPTH : integer := 16; WIDTH : integer := 8)` に置き換える。残りのコードはそのまま動くべき。
- **ファイルから内容を読む**。実プロジェクトは `init_from_file()` か、別の定数 package で ROM を読み込む。エラボレーション時に `textio` + `hread` で hex 値のテキストファイルを VHDL に読ませてみる。
- **2 つ目の読み出しポートを追加**。シングルサイクル CPU の命令/データメモリのような用途。このパターンはカリキュラム後半の CPU プロジェクトで見る。
