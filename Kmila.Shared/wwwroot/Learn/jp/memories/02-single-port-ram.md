# サンプル:write-first 読み出しのシングルポート RAM

読み書き可能メモリは、「BRAM を推論させる」ことのもう半分だ。同じ `type…array…of` のパターンが使えるが、今度は配列が **signal** であり、あるクロックエッジで書き込み、別のエッジで読み出す。

## テンプレート

```vhdl
type mem_t is array(0 to 31) of std_logic_vector(7 downto 0);
signal mem : mem_t := (others => (others => '0'));
...
process(clk)
begin
  if rising_edge(clk) then
    if we = '1' then
      mem(to_integer(unsigned(addr))) <= din;
      dout <= din;                             -- write-first 読み出し
    else
      dout <= mem(to_integer(unsigned(addr)));
    end if;
  end if;
end process;
```

なぜ `variable` や定数ではなく **signal** なのだろうか? この配列は、クロックエッジをまたいで持続し、実行時に *書き換えられる* 共有状態でなければならない — それはまさに signal そのものだ。定数(ROM のサンプルのような)は書き込めず、プロセスの variable はプロセスの外から見えない。そして、あらゆるアクセスが `rising_edge(clk)` の中にあるので、書き込みも読み出しも **同期** だ — それが、全体を block RAM にマップできるようにしているのだ。

## 3 つの読み出しポリシー

すべての同期 RAM は、読み出し中のアドレスへの **書き込みの最中** に `dout` が何をするかを決めなければならない。この「書き込み中の読み出し(read-during-write)」の振る舞いには 3 つの標準的な慣例があり、プロセスの形がどれになるかを選ぶ:

- **Write-first**(read-through とも呼ばれ、上に示したもの):書き込み時、`dout` は新しく書き込まれたデータを示す。最もきれいな意味論 — 同じアドレスへの読み出しと書き込みが同じサイクルに起きても、新しい値が得られる。
- **Read-first:** 書き込み時、`dout` はセルの **古い** 内容を示す。一部の CPU のレジスタファイルがこれを使う。
- **No-change:** 書き込み時、`dout` はまったく更新されず、直前の値を保持する。書き込み時に出力レジスタがトグルしないので、低電力設計でよく使われる。

違いは純粋に、プロセス内の 2 つの代入の *順序* だけだ:

```vhdl
-- READ-FIRST:古いデータを取り込んでから上書きする
if we = '1' then
  dout <= mem(to_integer(unsigned(addr)));   -- 古い値を出す
  mem(to_integer(unsigned(addr))) <= din;    -- そのあと書き込む
end if;

-- NO-CHANGE:書き込んでいないときだけ dout を更新する
if we = '1' then
  mem(to_integer(unsigned(addr))) <= din;    -- dout はそのまま
else
  dout <= mem(to_integer(unsigned(addr)));
end if;
```

3 つとも、現代のあらゆる FPGA で block RAM にマップされ、真のデュアルポート RAM の各ポートは別々のモードを使うことすらできる。ただしシンセサイザはプロセスの *正確な* 形からモードを選ぶので、実際に欲しい振る舞いにテンプレートを合わせよう。write-first 形が最も広く移植可能だ — 迷ったら、これを書こう。

## サンプルが行うこと

最初の 30 µs の間、シミュレーションは 3 つのアドレス(`0`、`1`、`2`)に 3 つの異なるバイトパターンを書き込む。それから `we` が下がり、40 µs で `addr` が 0 にリセットされる。Waveforms タブでは、書き込み中は `dout` が `din` に追従し、その後の読み出しでは格納された値が出てくるのが見える — アドレスを提示してから 1 サイクル後だ。読み出しがレジスタに通されているからだ。

## 気をつけること

- **アドレス幅と深さ。** ROM と同様に、`to_integer(unsigned(addr))` は `0 .. 31` の中に留まらなければならない。`addr` を `log2(DEPTH)` ビットにして、過剰なインデックスが起きないようにしよう。
- **組合せで読まないこと。** 組合せの読み出し(クロック付きプロセスの外の `dout <= mem(...)`)は、たいてい BRAM の推論を妨げ、配列をフリップフロップ/LUT に押し込める — 十数バイトなら問題ないが、キロバイト単位では致命的だ。
- **初期化子は保証されない。** `signal mem := (others => ...)` の初期値は、シミュレーションと多くの FPGA(BRAM に電源投入時の状態があるもの)では効くが、すべてのターゲットで効くわけではなく、電源投入時に未定義になる本物の外部 SRAM/DRAM では決して効かない。デバイスを確認せずに、プロダクションでこれに頼ってはいけない。

## あなたの番

- **真のデュアルポート RAM にアップグレードする。** `addr`/`din`/`dout`/`we` のフルセットを 2 組、両方とも `clk` でクロックする。これは各ベンダの FIFO やデュアルクロック DPRAM が裏で使っているパターンだ。
- **出力レジスタを追加する。** block RAM は、メモリ配列の後にもう 1 つパイプラインレジスタをサポートする。2 つ目のクロック付きブロックで `dout_reg <= dout;` を追加し、波形で何が変わるか見てみよう(ヒント:レイテンシが 1 サイクル増えるが、タイミングクロージャは格段に良くなる)。
- **その上に FIFO を構築する。** RAM を書き込みポインタ、読み出しポインタ、`full`/`empty` フラグで包む。これが同期 FIFO の標準的な作り方で、この単元で名指しで求められているものだ。

## コースとのつながり

これは単元 IV *Memorias*(メモリ)の核心だ:RAM / SRAM / DRAM と、配列の扱いを通じた RAM、ROM、**FIFO** メモリの HDL 設計。write-first / read-first / no-change は、本物の SRAM セルが示す書き込み中読み出しの振る舞いの HDL での顔だ。上の FIFO の練習は、この単元が挙げる *tipos especiales de memorias*(特殊なメモリの種類)そのものだ。

## 覚えておくべきこと

- 読み書き可能メモリ = ROM と同じ配列パターン。ただし実行時に書き込む **signal** だ。
- 読み出しと書き込みの両方を `rising_edge(clk)` の中に置き、ツールに block RAM を推論させよう。
- write-first / read-first / no-change は、プロセス内の文の順序で選ばれる — 設計が必要とするものを選ぼう。write-first が安全なデフォルトだ。
- アドレス幅に注意し、組合せ読み出しを避け、BRAM の初期化子をすべてのターゲットで信用しないこと。
