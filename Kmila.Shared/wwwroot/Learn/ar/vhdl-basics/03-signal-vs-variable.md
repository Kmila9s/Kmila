# الإشارة مقابل المتغيِّر

هذا أكثر تمييز يُساء فهمه في VHDL على الإطلاق. يقرأ الطلَّاب «المتغيِّر مثل متغيِّر محلِّي في C» وينطلقون في الاتجاه الخطأ. لنُثبِّت الأمر على أرض صلبة، لأن إتقانه هو ما يفصل بين شفرة *تُحاكى فحسب* وشفرة *تصير العتاد الذي قصدته*.

## نوعان من الأسماء في VHDL

في VHDL **إشارات** (تُعلَن على مستوى architecture بـ `signal`) و**متغيِّرات** (تُعلَن داخل process بـ `variable`). كلاهما قادر على حفظ القيم. وكلاهما قابل للإسناد. لكنهما **ليسا** متبادلين.

| | الإشارة | المتغيِّر |
|---|---|---|
| تُعلَن في | architecture (أو حزمة) | داخل process/برنامج فرعي |
| عامل الإسناد | `<=` | `:=` |
| تدخل حيِّز التنفيذ | في نهاية خطوة المحاكاة | فورًا |
| النطاق | مشترك عبر architecture كلها | محلِّي بالنسبة لمعالجته |
| يُنمذج | سلكًا أو مسجِّلًا | حسابًا مؤقَّتًا |

## القاعدة الذهبيَّة

- **إسنادات الإشارات *مُجدوَلة*؛ تظهر القيمة في نهاية خطوة المحاكاة الحاليَّة.**
- **إسنادات المتغيِّرات تحدث فورًا، في موضع السطر ذاته.**

ذلك كل شيء. كل «شَرَك» بين الإشارات والمتغيِّرات هو إعادة صياغة لهذه القاعدة.

## العرض

```vhdl
architecture demo of ex is
  signal s : integer := 0;
begin
  process(clk)
  begin
    if rising_edge(clk) then
      s <= 1;           -- جدولة: اضبط s إلى 1 (ليست مرئيَّة بعد)
      s <= 2;           -- جدولة: اضبط s إلى 2 (تلغي الأولى)
      -- ما قيمة s هنا؟ لا تزال 0. لم يدخل أيُّ إسناد حيِّز التنفيذ.
    end if;
  end process;
end architecture demo;
```

بعد اكتمال حافة الساعة، تصير `s` تساوي **2** — فحين تُجدوَل إشارة عدَّة مرَّات في تمريرة معالجة واحدة، يفوز الإسناد *الأخير* فقط. أما داخل المعالجة، بعد الإسنادَين، فتبقى `s` تساوي `0`، لأن القيمة الجديدة لا تنتشر حتى تنتهي المعالجة.

الآن بمتغيِّر:

```vhdl
architecture demo of ex is
begin
  process(clk)
    variable v : integer := 0;   -- المتغيِّر يعيش داخل المعالجة
  begin
    if rising_edge(clk) then
      v := 1;           -- يدخل حيِّز التنفيذ فورًا
      v := 2;           -- يدخل حيِّز التنفيذ فورًا
      -- v هي 2 هنا، الآن، خلال هذه التمريرة
    end if;
  end process;
end architecture demo;
```

لاحظ شيئَين:

- المتغيِّرات تستخدم `:=`؛ الإشارات تستخدم `<=`.
- المتغيِّرات محلِّيَّة لمعالجة واحدة — لا يمكنك قراءة `v` من معالجة أخرى أو من إسناد تزامني.

> دقيقة واحدة بخصوص القيمة الابتدائيَّة: `variable v : integer := 0;` يُنفِّذ `:= 0` **مرَّة واحدة** فقط، عند بدء المحاكاة — لا في كل تمريرة معالجة. يحتفظ المتغيِّر بقيمته بين التمريرات ما لم تُعِد إسناده. هذا ما يجعله قادرًا على *التذكُّر*، وهو السبب في أن متغيِّرًا يُقرأ قبل أن يُكتَب داخل معالجة متزامنة قد يستنتج مسجِّلًا دون قصد.

## لماذا يهمُّ هذا للعتاد

الإشارة **تُنمذج سلكًا أو قلَّابًا**. لا يمكنك تغيير قيمة سلك مرَّتَين في اللحظة ذاتها — فما يقود السلك خلال خطوة يستقرُّ على قيمة واحدة في نهاية تلك الخطوة.

المتغيِّر **يُنمذج حسابًا مؤقَّتًا** داخل معالجة. يُنفِّذه المُخلِّق عادةً كمنطق توافقي يُغذِّي المسجِّلات (أو يخرج منها) — أو يحذفه بالكامل في التحسين.

## مثال محلول: عدُّ البتات المرفوعة

يتألَّق المتغيِّر حين تحتاج نتيجة وسيطة تُحدِّثها داخل حلقة:

```vhdl
process(clk)
  variable ones : integer range 0 to 8;
begin
  if rising_edge(clk) then
    ones := 0;                      -- صفِّر المُراكِم في كل تمريرة
    for i in data'range loop
      if data(i) = '1' then
        ones := ones + 1;           -- تحديث فوري، يُقرأ في التكرار التالي
      end if;
    end loop;
    popcount <= ones;               -- انشر العدَّ النهائي على إشارة
  end if;
end process;
```

جرِّب هذا بإشارة بدل متغيِّر وسينكسر: `ones <= ones + 1` داخل الحلقة سيُجدوِل ثمانية إسنادات متنافسة، لا يبقى منها إلَّا الأخير، فتحصل دومًا على `0` أو `1`. الحلقة تحتاج الدلالة *الفوريَّة* للمتغيِّر.

## متى تستخدم أيًّا

- **الإشارات** — الافتراضي. كل منفذ، وكل مسجِّل، وكل ناقل ستراه في عارض أشكال الموجة: إشارة.
- **المتغيِّرات** — لعدَّادات حلقات محلِّيَّة أو نتائج حسابيَّة وسيطة داخل معالجة واحدة، حيث تريد دلالة شبيهة بـ C: «اقرأ ما كتبته للتوّ».

## فخّ شائع

يكتب بعض الطلَّاب:

```vhdl
process(clk)
begin
  if rising_edge(clk) then
    a <= b;    -- مسجِّل 1
    b <= a;    -- مسجِّل 2
  end if;
end process;
```

يقلقون من أنَّه لن يُبادل بين `a` و`b`. لكن لأن إسنادات الإشارات مُجدوَلة، فإنه **يُبادل** فعلًا: عند الحافة، تأخذ `a` قيمة `b` **القديمة**، وتأخذ `b` قيمة `a` **القديمة**، في وقت واحد. هذه فعلًا الطريقة الاصطلاحيَّة لتبديل مسجِّلَين في دورة واحدة.

لكن انتقل إلى المتغيِّرات وتنقلب الدلالة:

```vhdl
process(clk)
  variable a, b : integer;
begin
  if rising_edge(clk) then
    a := b;    -- a الآن تساوي b
    b := a;    -- b تأخذ a الجديدة — فتبقى b بقيمتها القديمة، وتتغيَّر a
  end if;
end process;
```

لا تبديل. ينتهي كلاهما مساويًا قيمة `b` القديمة. شفرة متشابهة المظهر، نتيجة معاكسة — وكل ذلك بسبب القاعدة الذهبيَّة.

## ما يجب تذكُّره

- `signal`: القيمة مُجدوَلة، تظهر في نهاية الخطوة؛ إسناد `<=`؛ يُنمذج الأسلاك والمسجِّلات؛ مشترك عبر architecture كلها.
- `variable`: يتحدَّث فورًا؛ إسناد `:=`؛ محلِّي لمعالجة؛ يُنمذج الحساب الوسيط.
- عدَّة إسنادات إشارة في تمريرة واحدة ← يفوز الأخير. عدَّة إسنادات متغيِّر ← تُنفَّذ كلها، بالترتيب.
- عند الشكّ — استخدم إشارة.
