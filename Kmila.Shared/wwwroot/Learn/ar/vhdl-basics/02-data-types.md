# أنواع البيانات: `std_logic` والمتجهات و`unsigned` و`integer`

VHDL لغة **قويَّة التنميط (strongly typed)**. حين ترى منفذًا مُعلَنًا `in std_logic`، لن يسمح لك المترجم بوصله بشيء من نوع مختلف دون تحويل صريح. اختيار النوع الصحيح لكل إشارة هو نصف الطريق إلى كتابة VHDL نظيفة.

## `std_logic` — السلك الكوني

بِت واحد من منطق IEEE 1164 ذي **القيم التسع**. نعم، تسع:

| القيمة | المعنى |
|-------|---------|
| `'0'` | تشغيل قوي منخفض |
| `'1'` | تشغيل قوي مرتفع |
| `'Z'` | ممانعة عالية (tristate مُطفأ) |
| `'L'` | منخفض ضعيف (pull-down) |
| `'H'` | مرتفع ضعيف (pull-up) |
| `'X'` | مجهول قوي — مثلًا مُشغِّلان يتنازعان بقيمتين مختلفتين |
| `'U'` | غير مُهيَّأ — إشارتك لم تُسنَد إليها قيمة قط |
| `'W'` | مجهول ضعيف |
| `'-'` | لا يهمّ (يُستخدَم نمطًا لـ `std_match` / تلميحًا للتخليق) |

لماذا تسع بدل اثنتين؟ لأن السلك الحقيقي ليس مجرَّد «0 أو 1». يمكن أن يكون طافيًا (`'Z'`)، أو مشدودًا شدًّا ضعيفًا (`'L'`/`'H'`)، أو في تنازع حقيقي (`'X'`). هذا ما يجعل `std_logic` نوعًا **مُحلَّلًا (resolved)**: حين يتشارك عدَّة مُشغِّلات سلكًا واحدًا، تقرِّر دالة تحليل النتيجة. القيمة القويَّة تغلب الضعيفة؛ وقيمتان قويَّتان متعارضتان تُنتِجان `'X'`؛ والسلك غير المُشغَّل يستقرُّ على `'Z'`.

في التخليق تصل `'0'` و`'1'` و`'Z'` فقط إلى العتاد. الباقي أدوات تشخيص للمحاكاة — إن رأيت `'U'` في مخطَّط موجة فلديك إشارة تُقرأ قبل أن تُكتَب؛ وشريط من `'X'` يعني غالبًا ناقلًا بمُشغِّلين نشطين.

> يوجد أيضًا قريب غير مُحلَّل هو `std_ulogic` (الـ `u` تعني «غير مُحلَّل»). `std_logic` حرفيًّا هو `std_ulogic` مضافًا إليه دالة تحليل. استخدم `std_logic` افتراضيًّا — فالتحليل هو ما تريده للنواقل.

## `std_logic_vector` — ناقل

مصفوفة ثابتة العرض من `std_logic`:

```vhdl
signal data : std_logic_vector(7 downto 0);  -- 8 بتات، فهارس 7..0
signal addr : std_logic_vector(0 to 15);     -- 16 بتًا، فهارس 0..15
```

`downto` هو الاتجاه الأكثر شيوعًا بفارق كبير — فهو يطابق طريقتنا في كتابة الأعداد (البِت الأعلى على اليسار، فـ `data(7)` هو البِت الأعلى قيمةً). اختر اتجاهًا واحدًا للمشروع والتزم به؛ فخلط `to` و`downto` مصدر كلاسيكي لنواقل تُعكَس بصمت.

الثوابت الحرفيَّة:

```vhdl
data <= "10101010";      -- ثابت ثنائي، محرف لكل بِت
addr <= x"CAFE";         -- ثابت ست عشري (يجب أن يكون العرض مضاعفًا لـ 4 بتات)
data <= (others => '0'); -- تجميع: أصفار كلها، بأي عرض
data <= (0 => '1', others => '0'); -- البِت 0 (الأدنى) فقط مرتفع
```

صيغة `(others => '0')` تستحقُّ أن تحبَّها: فهي تتكيَّف تلقائيًّا إن غيَّرت العرض لاحقًا، فلا تتقادم أبدًا.

## `unsigned` / `signed` — متجهات تستطيع إجراء الحساب عليها

`std_logic_vector` هو «مجرَّد كيس من البتات». لا معنى عددي له، فـ `slv1 + slv2` خطأ ترجمة مع `numeric_std`. لتجمع أو تطرح، تحتاج `unsigned` أو `signed`:

```vhdl
use IEEE.NUMERIC_STD.ALL;

signal a, b, sum : unsigned(7 downto 0);
...
sum <= a + b;   -- يعمل: جمع unsigned بنفس العرض
```

النوعان يختلفان فقط في كيفية قراءة البِت الأعلى: `unsigned` يعامل كل البتات مقدارًا؛ و`signed` يعامل البِت الأعلى إشارةً بنظام المتمِّم الثنائي.

التنقُّل بينها — هذه هي التحويلات الأربعة التي ستستخدمها باستمرار:

```vhdl
-- إعادة تفسير نفس البتات كـ unsigned (للحساب)
u   <= unsigned(slv);

-- إعادة تفسير unsigned كبتات صِرفة (للعالم الخارجي / لمنفذ)
slv <= std_logic_vector(u);

-- unsigned -> integer، للفهرسة أو الثوابت
idx <= to_integer(u);

-- integer -> unsigned؛ يجب أن تعطي العرض
u   <= to_unsigned(42, 8);
```

`unsigned(slv)` و`std_logic_vector(u)` **صبُّ أنواع (type casts)** — يغيِّران اللافتة على البتات لا البتات نفسها. أما `to_integer` و`to_unsigned` فهما **دالتان** تحسبان فعلًا. من الأخطاء الشائعة للمبتدئين استدعاء `to_unsigned` على متجه (وهي تأخذ عددًا صحيحًا) أو صبُّ عدد صحيح بـ `unsigned(…)` (فالصبُّ لا يعمل إلَّا بين أنواع المصفوفات).

وواحدة أخرى تنقذك من أخطاء الطفحان — `resize`، التي تُحشِّي أو تقصُّ إلى عرض جديد. تُمدِّد `unsigned` بالأصفار و`signed` بالإشارة، فتحفظ القيمة قبل الحساب:

```vhdl
wide <= resize(a, 9) + resize(b, 9);  -- نتيجة 9 بتات تحفظ المحمول
```

قاعدة عامَّة: استخدم `std_logic_vector` في **المنافذ** (الجمهور الأوسع)، وحوِّل إلى `unsigned` / `signed` داخل الـ architectures حيث تجري الحساب فعلًا.

## `integer` — للفهرسة والعدّ

استخدم `integer` (أو نوعًا فرعيًّا مُقيَّدًا) لعدَّادات الحلقات والثوابت وكل ما لن يعبر حدود منفذ:

```vhdl
constant DEPTH : integer := 32;
for i in 0 to DEPTH - 1 loop ...
```

الـ `integer` غير المُقيَّد لا يقلُّ عن 32 بِتًا في المحاكاة (المدى من ‎−2³¹+1‎ إلى ‎2³¹−1‎). أما للعتاد فتريد غالبًا مدًى مُقيَّدًا كي يُحجِّم المُخلِّق المسجِّل بالقدر المناسب:

```vhdl
signal counter : integer range 0 to 255;  -- يتخلَّق إلى 8 بتات بالضبط
```

عدَّاد `integer` غير مُقيَّد سيكلِّفك 32 قلّابًا لم ترغب بها.

## التعدادات — لحالات آلة الحالات

أعلِن نوعًا مقروءًا لآلات الحالات:

```vhdl
type state_t is (S_IDLE, S_START, S_ACTIVE, S_DONE);
signal state : state_t;
```

عندئذٍ تكتب `state <= S_ACTIVE` بدل `state <= "010"`. يختار المُخلِّق لك الترميز الثنائي (أو one-hot)، ويمكنك أن تلمِّح له بـ attribute إن كان يهمُّك. تصير شفرتك أشبه بمواصفة، ويُظهِر مخطَّط الموجة *أسماء* الحالات لا بتاتها الخام.

## ما يجب تذكُّره

- سلك واحد ← `std_logic`. ناقل ← `std_logic_vector`. كلاهما من `STD_LOGIC_1164`.
- تحتاج إجراء حساب؟ استخدم `unsigned` (أو `signed`) و`IEEE.NUMERIC_STD`. `std_logic_vector` لا معنى عددي له.
- `unsigned(x)` / `std_logic_vector(x)` صبُّ أنواع (إعادة وسم البتات)؛ و`to_integer` / `to_unsigned` دالتان (و`to_unsigned` تحتاج عرضًا).
- إعلان **المنافذ** بـ `std_logic_vector` يجعل الـ entity قابلة للنقل إلى أقصى حدّ؛ حوِّل في الداخل.
- قيِّد مدى الـ `integer`، واستخدم التعدادات لحالات آلة الحالات.
