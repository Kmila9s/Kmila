# مشروع: آلة بيع تعمل بالعملات

هذا أوَّل مشروع حقيقي لك. المواصفات مثبَّتة، وشفرة البداية تُسلِّمك السباكة، وعملك أن تكتب المنطق الذي يُكمِلها.

## ما الذي تبنيه

آلة حالات تتتبَّع المال الذي أدخله الزبون وتُسلِّم منتجًا (نبضة خرج واحدة، `dispense`) حين تبلغ الجملة 25¢. المداخل:

- `nickel` — نبضة بدورة واحدة معناها «سقطت قطعة 5¢ توًّا»
- `dime` — نبضة بدورة واحدة معناها «سقطت قطعة 10¢ توًّا»
- `clk`، `reset`

والمخارج:

- `dispense` — نبضة مرتفعة لدورة ساعة واحدة بالضبط حين تبلغ ≥ 25¢
- `change` — نبضة مرتفعة لدورة واحدة بجانب `dispense` إن كانت الجملة **أكثر** من 25¢ (فتحتاج الآلة إلى إرجاع مال)

## طريقتان لنمذجة هذا

آلة البيع آلة حالات كلاسيكيَّة، وهناك طريقتان أمينتان لوصفها:

- **حالات صريحة.** عدِّد كل جملة يمكن بلوغها — `S0, S5, S10, S15, S20` — وارسم انتقالًا لكل عملة. هذه مقاربة الكتاب، وما كنت لتفعله يدويًّا لمجموعة عملات صغيرة. تجعل مخطَّط الحالات بديهيًّا، لكنها تنفجر إن أضفت عملات أكثر أو سعرًا أعلى.
- **أسلوب المُجمِّع (مسار البيانات).** احفظ الجملة في سجل صغير وقارنها بالسعر. أسطر أقلّ، يتوسَّع لأي سعر، وهو الشكل الذي تستخدمه شفرة البداية. يمكنك أن تعدَّ سجل `total` هو الحالة، والمقارِن هو منطق الحالة التالية.

في الحالتَين، يعتمد `dispense` على وصول العملة في *هذه* الدورة، فيتصرَّف كخرج **Mealy** — يستجيب في الدورة نفسها التي يصبح فيها شرط البيع صحيحًا، بدل أن ينتظر دورة.

## ما تمنحك إيَّاه البداية

الكيان ومُجمِّع `total` موصولان. كل نبضة `nickel` تضيف 5؛ وكل نبضة `dime` تضيف 10. لكن البداية تدفع دومًا `dispense = '0'` و`change = '0'`. **هذا ما عليك تغييره.**

```vhdl
process(clk, reset)
begin
  if reset = '1' then
    total <= (others => '0');
  elsif rising_edge(clk) then
    if    nickel = '1' then total <= total + 5;
    elsif dime   = '1' then total <= total + 10;
    end if;
  end if;
end process;

dispense <= '0';  -- TODO
change   <= '0';  -- TODO
```

## مقاربة مقترحة

1. **اكتشف شرط البيع.** عند كل حافة ساعة صاعدة، تحقَّق إن كان `total >= 25` *بعد* إضافة العملة الحاليَّة. (انتبه: عليك حساب الجملة *الجديدة*، لا تلك من الدورة السابقة.)
2. **انبِض `dispense` لدورة واحدة بالضبط.** الحيلة: حين تكتشف البيع، عيِّن النبضة وأعِد `total` إلى صفر. ولأنَّ `total` يُصفَّر على الحافة نفسها، يصبح الشرط خاطئًا في الدورة التالية، فتكون النبضة بعرض دورة واحدة طبيعيًّا.
3. **احسب `change`.** إن كانت الجملة لحظة البيع > 25، انبِض `change` أيضًا.

احسب «الجملة التالية» كـ `variable` داخل المعالجة كي يستخدم القرار القيمة المُحدَّثة، لا قيمة سجل الدورة السابقة:

```vhdl
process(clk, reset)
  variable next_total : unsigned(5 downto 0);
begin
  if reset = '1' then
    total    <= (others => '0');
    dispense <= '0';
    change   <= '0';
  elsif rising_edge(clk) then
    next_total := total;
    if    nickel = '1' then next_total := total + 5;
    elsif dime   = '1' then next_total := total + 10;
    end if;

    if next_total >= 25 then
      dispense <= '1';
      if next_total > 25 then change <= '1'; else change <= '0'; end if;
      total    <= (others => '0');
    else
      dispense <= '0';
      change   <= '0';
      total    <= next_total;
    end if;
  end if;
end process;
```

تنبَّه لأمرَين. الـ `variable` يُسنَد بـ `:=` ويتحدَّث **فورًا** داخل المعالجة، وهذا بالضبط سبب أنَّ `next_total` يتضمَّن أصلًا عملة هذه الدورة — بينما إشارة (`<=`) لن تتحدَّث حتَّى تتوقَّف المعالجة. ولأنَّ `dispense` و`change` و`total` تُقاد كلُّها داخل المعالجة المُساعَة بالساعة، فهي **مُسجَّلة** — تتحاذى النبضات مع حافات الساعة ولا تقفز.

## انتبه إلى

- **العرض.** يمكن لـ `total + 10` أن يبلغ 30 قبل أن ينطلق التصفير، فأعطِ السجل 6 بتات على الأقلّ — `unsigned(5 downto 0)` يحمل 0–63 مع مُتَّسع. الشعاع الضيِّق جدًّا يلتفُّ بصمت.
- **العملتان معًا.** صيغة `if … elsif` تعني أنَّ `nickel` و`dime` آنيَّين تُحسَب منهما الـ nickel فقط. قرِّر هل هذا مقبول أم خطأ لمواصفتك.
- **نسيان تصفير `total`.** إن نبضتَ `dispense` ولم تُصفِّر المُجمِّع، «باعت» الآلة من جديد في كل دورة حتَّى تُغيِّر عملات أخرى الجملة. التصفير على حافة البيع هو ما يجعل النبضة بعرض دورة واحدة.

## معايير القبول

| تتابع العملات        | السلوك المتوقَّع              |
|----------------------|-------------------------------|
| 5 قطع nickel         | `dispense=1, change=0`        |
| 2 dime + 1 nickel    | `dispense=1, change=0`        |
| 3 dime (= 30¢)       | `dispense=1, change=1`        |
| 2 nickel + 1 dime    | لا تسليم (20¢ فقط)            |

## للمضي أبعد

- أضف زر **استرداد** يُصفِّر `total` بلا تسليم.
- ادعم قطعة **quarter** (25¢) — يجب أن تُسلِّم فورًا.
- تتبَّع عدد القطع المباعة في عدَّاد 8 بت منفصل ظاهر كخرج. هذا نوع التغذية الراجعة الذي ترسله آلات البيع الحقيقيَّة إلى أعلى.

## الصلة بالمساق

هذا هو *التطبيقات بالمؤتمتات ولغة وصف العتاد* من الوحدة الثانية: آلة تتابعيَّة حتميَّة محدَّدة من سلوك، ثم موصوفة بـ HDL. وشكل المُجمِّع-مع-المقارِن هو أيضًا مدخل لطيف إلى الوحدة الخامسة، حيث ستقسم تصميمًا صراحةً إلى **مسار بيانات** (سجل `total` والجامع) و**مؤتمتة تحكُّم** تقوده.

## ما يجب تذكُّره

- آلة البيع آلة حالات؛ انمذِجها بحالات صريحة للوضوح، أو بسجل مُجمِّع للتوسُّع.
- استخدم `variable` (`:=`) لـ «الجملة التالية» كي يتضمَّن فحص البيع العملة التي وصلت توًّا.
- اصنع نبضة بعرض دورة واحدة بتصفير المُجمِّع على حافة البيع — الخرجات المُسجَّلة تُبقي النبضة نظيفة.
- قِس الأشعِعة لأكبر قيمة يمكن أن تبلغها، وقرِّر مسبقًا كيف تتصرَّف المداخل الآنيَّة.
